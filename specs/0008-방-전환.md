## 목적
방을 여러 개 가진 사용자가 홈 상단 "방이름▾"(또는 **하단 네비 홈 버튼 롱프레스**)으로 진행중/종료된 방 목록을 보고 즉시 전환하거나, 새 방을 만들거나 초대코드로 참여하게 한다. 이 화면이 구현되면 `specs/OPEN.md` 미결 항목 1번("현재 방 첫 번째 ACTIVE로 임시 대체")이 해소된다.

> **2026-07-30 트리거 변경**: `full_spec.md` §3-5의 보조 트리거 "홈 화면 롱프레스"는 **하단 네비 홈 버튼 롱프레스로 대체**됐다(사용자 확정, `specs/OPEN.md` 확정 기록). 원본(`full_spec.md`)은 보존 규칙에 따라 수정하지 않는다. 홈 화면 본문 롱프레스는 구현하지 않는다.
>
> **2026-08-07 재구성**: 시트 = ① 헤더 [제목 "방 전환" + (**종료된 방이 있을 때만**) 우측 "종료된 방 보기 ›"(꺽쇠 `angle_bracket.png`) → S-40-D `/mypage/past-rooms`] ② 카드 [**활동중(ACTIVE) 방 전부** + "방 만들기" 아이템] ③ 하단 풀폭 **"초대코드로 입장하기"**(→ S-11 `/room/join`). **종료된 방은 목록에서 제외**하고 헤더 "종료된 방 보기"로만 접근(기존 "종료방 3개 미리보기 + …더보기" 방식 폐기). 아래 line 22 레이아웃·line 29 "…더보기"·기존 종료방 인라인 노출은 이 노트로 대체.

## 롱프레스 코치마크 (최초 사용자 유도)

롱프레스는 발견 가능성이 거의 없는 제스처라, **한 번도 써본 적 없는 사용자**에게 하단 네비 홈 버튼을 스포트라이트로 비춰 그 자리에서 직접 해보게 한다. 규격은 `specs/design.md` §6 "코치마크(스포트라이트)".

| 단계 | 노출 조건 | 횟수 |
|---|---|---|
| 1단계(intro) | 최초 홈 진입. **진행중 방이 1개뿐이어도 무조건** 보여준다(사용법 자체를 먼저 각인). 아래 **2스텝 투어** | 1회 |
| 2단계(multi) | ACTIVE 방이 **2개 이상**이 된 뒤 홈 진입(실제로 쓸 이유가 생긴 시점). **단일 스텝**(홈 버튼만) | 1회 |

### 1단계 = 2스텝 투어 (2026-08-09 QA 확정)
최초 진입 코치마크는 **네비바 홈 → 멤버 아바타** 2스텝으로 안내한다. 두 스텝 모두 **바깥/구멍 단순 탭으로는 닫히지 않고**, 말풍선 하단 **버튼으로만** 진행·종료한다.
- **스텝1(네비바 홈)**: 홈 버튼 스포트라이트 + "홈을 꾹 누르면 방을 바꿀 수 있어요". 구멍 롱프레스 실습은 **유지**(누르면 S-07 시트가 열리고 `used`로 기록·투어 종료). 말풍선 하단 **`다음`** 버튼 → 스텝2로.
- **스텝2(멤버 아바타)**: 홈 첫 번째 **비-본인** 멤버 아바타를 스포트라이트(말풍선은 아바타 **아래**) + "팀원을 눌러 콕 찔러보세요 / 진행 상황을 보고 콕 찔러 독려할 수 있어요". 말풍선 하단 **`완료`** 버튼 → 종료(`intro_shown` 기록). 타 멤버가 없는 솔로 방이면 스텝2를 건너뛰고 `다음`이 바로 종료한다.
- 아바타 위치는 홈 화면이 그리므로, 셸이 위치를 읽도록 홈이 첫 비-본인 아바타에 전역 앵커(`homeFirstMemberAvatarKey`, `app/lib/features/home/home_coach_anchors.dart`)를 부착한다.
- **2단계(multi)는 기존 단일 스텝 그대로** — 홈 버튼만 비추고 **바깥 탭으로 닫힌다**(버튼 없음).

- **두 단계 모두 "네비바 롱프레스로 시트를 연 적 없음"을 전제**로 한다. 사용자가 한 번이라도 롱프레스로 시트를 열면 이후 어느 단계도 노출하지 않는다.
- 홈 탭에 있을 때만 노출한다(홈 버튼을 가리키는 안내라, 다른 탭 위에 dim이 뜨지 않게).
- 영속화는 `shared_preferences` 키 3개: `room_switch_longpress_used`, `room_switch_hint_intro_shown`, `room_switch_hint_multi_shown` (구현: `app/lib/features/room/room_switch_hint.dart`).
- 방 개수는 실행 중에도 늘어날 수 있으므로(방 참여·생성 직후) `RoomSession` 변경 알림을 받아 2단계를 다시 판정한다.

**구현 주의(실측)**: `NavigationDestination` 내부 `Tooltip`이 롱프레스 제스처를 먼저 가져가므로, `NavigationBar`를 감싸는 `GestureDetector`로는 롱프레스를 받을 수 없다. 홈 칸 위에 `HitTestBehavior.translucent` 레이어를 얹어 롱프레스만 가로채고 탭은 아래로 통과시킨다.

## 데이터 (엔티티 연결)
- 목록 소스: `GET /rooms`(이미 구현됨, `RoomSummaryResponse` — id/name/goal/status/startDate/endDate) 중 `status = ACTIVE`는 전체, `status = ENDED`는 최근 것부터 최대 3개.
- **"현재 방" 컨텍스트 영속화**: 사용자가 방을 탭해 전환하면 그 `roomId`를 "마지막으로 본 방"으로 클라이언트에 저장(예: `AppSession`에 필드 추가 또는 로컬 저장소). `specs/0003-navigation.md`의 재진입 리다이렉트("마지막 본 방 ACTIVE → 그대로 노출")가 이 값을 사용한다.
- **정렬**: 진행중 방 목록의 정렬 기준(최근 열어본 순 vs 생성순 등)은 원본 문서에 명시가 없다 — `specs/OPEN.md`에 신규 미결 항목으로 기록하고 확정 전까지는 "최근 열어본 순(마지막 본 방이 최상단)"을 임시값으로 둔다.

## 성공(인수) 기준
- [ ] 홈 상단 "방이름▾" 탭 또는 하단 네비 홈 버튼 롱프레스 시 S-07 시트가 뜬다.
- [ ] 투두/일정/아카이브 탭에서 홈 버튼을 롱프레스해도 탭이 이동하지 않고 시트만 열린다.
- [ ] 홈이 아닌 탭 버튼(투두/일정/아카이브)을 롱프레스하면 아무 일도 일어나지 않는다.
- [ ] 최초 홈 진입 시 진행중 방이 1개뿐이어도 코치마크가 1회 뜨고, `다음`→`완료`(또는 솔로 방은 `다음` 한 번)로 종료하면 다시 뜨지 않는다.
- [ ] intro 투어는 바깥/구멍 단순 탭으로 닫히지 않고, 말풍선 하단 버튼(`다음`/`완료`)으로만 진행·종료한다. 2스텝(네비바 홈 → 멤버 아바타)이 순서대로 뜬다.
- [ ] ACTIVE 방이 2개 이상이 되면 코치마크(단일 스텝, 바깥 탭으로 닫힘)가 1회 더 뜨고, 그 뒤로는 뜨지 않는다.
- [ ] 롱프레스로 방 전환을 한 번이라도 해본 사용자에게는 코치마크가 어느 단계도 뜨지 않는다.
- [ ] 코치마크의 구멍(홈 버튼)을 롱프레스하면 코치마크가 닫히고 그대로 S-07 시트가 열린다.
- [ ] 진행중인 방 전체가 목록에 보이고, 탭하면 즉시 그 방으로 전환되며 시트가 닫힌다.
- [ ] 종료된 방은 최대 2~3개까지 회색 톤 + "종료됨" 뱃지로 보이고, 4개 이상이면 "…" 버튼이 노출된다.
- [ ] 방 전환 후 앱을 재시작(재진입)하면 방금 전환한 방이 그대로 열린다(`specs/0003-navigation.md` "마지막 본 방" 로직과 연동, `specs/OPEN.md` 항목 1 해소).
- [ ] [+ 방 만들기]/[🔑 초대 코드 입력]을 탭하면 각각 S-10/S-11로 이동한다.

## 엣지케이스
- **진행중 방이 1개뿐**: 시트를 열 이유가 적지만 동일하게 동작(전환해도 같은 방으로 "재진입"). 막지 않는다.
- **방 전환 중 네트워크 실패**: 시트를 닫지 않고 인라인 에러 표시, 기존 컨텍스트 유지.
- **동시에 여러 종료된 방**: "최근 종료된 순" 최대 3개만 미리보기, 나머지는 전부 S-40-D에서.
