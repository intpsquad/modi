## 이메일 인증코드 API 계약 (S-02-A 1단계, 2026-07-31 확정)

프론트(3단계 폼)가 먼저 구현·병합됐고, 서버가 그 계약에 맞춰 두 엔드포인트를 추가했다. 상세 결정 근거는 `specs/OPEN.md` 확정 기록.

| 엔드포인트 | 요청 | 응답 |
|---|---|---|
| `POST /auth/email/code` | `{email}` | 200 발송 성공 · 409 이미 가입된 이메일 · (그 외 앱은 제네릭 실패 문구로 처리) |
| `POST /auth/email/code/verify` | `{email, code}` | 200 검증 성공 · 400 코드 불일치 · 410 코드 만료(5분 TTL 경과 또는 5회 오답으로 무효화) |

둘 다 `/auth/**`라 인증 없이 호출 가능(카카오 교환과 동일 이유). 코드는 Redis에만 저장(Postgres 테이블 없음). 재전송 쿨다운(60초)은 API 방어용이고, **프론트 재전송 버튼도 60초 카운트다운 뒤 활성**된다(2026-08-04 , 서버 쿨다운과 동일 — `signup_screen.dart _codeTimerRemaining=60`). 버튼을 누르면 발송 API(`POST /auth/email/code`)를 다시 호출해 코드를 재전송하고 타이머를 리셋한다.

앱은 디버그/릴리스 빌드를 구분해 이 단계를 우회하지 않는다. `AuthService`는 두 빌드 모두 실제 발송·검증 엔드포인트를 호출한다. 로컬에서 전체 흐름을 확인하려면 Redis와 SMTP 설정이 필요하며, 설정이 없으면 발송 API는 계약대로 503을 반환한다.

## 소셜 로그인 구현
- Google은 `google_sign_in`으로 credential을 만든 뒤 Firebase 세션으로 교환한다.
- Kakao는 SDK access token을 서버 `POST /auth/kakao`의 Firebase Custom Token으로 교환한다.
- Apple은 Firebase `AppleAuthProvider`의 네이티브 `signInWithProvider`를 사용한다. Apple ID credential이나 access/refresh token을 앱이 별도로 저장하지 않는다. iOS Runner에는 `com.apple.developer.applesignin` entitlement와 Sign in with Apple capability가 필요하다.
- Apple은 첫 승인 때만 이름·이메일을 제공할 수 있고, 이메일 비공개를 선택하면 `privaterelay.appleid.com` 주소를 제공하므로 신규 사용자 프로필 동기화와 메일 릴레이 설정을 별도로 고려한다.

## 데이터 (엔티티 연결)
- 로그인/가입 성공 시 Firebase가 ID 토큰(JWT) 발급 → 서버가 Admin SDK로 검증 후 `users` 테이블에 upsert(0001 인증 흐름). Kakao는 SDK access token을 서버의 `/auth/kakao`에서 Custom Token으로 교환한 뒤 Firebase 세션을 만든다. `users.nickname`은 자체가입은 폼 입력값, 소셜 가입은 제공자 프로필 닉네임을 사용하고, 신규 OAuth 사용자의 `profileImage`도 제공자 값을 기본값으로 저장한다. 프로필이 없거나 제공 동의가 없으면 닉네임은 `사용자` + 4자리 난수로 폴백하며, 기존 사용자의 설정 페이지 수정값은 유지한다.
- 자체가입 "아이디"는 이메일이다(0002 `users` 확정 사항, Firebase email/password).

## 엣지케이스
- **카카오 프로필 동의 거부**: Kakao 사용자 API가 닉네임을 주지 않으면 서버가 `사용자` + 4자리 난수를 생성한다. 이후 설정 페이지의 프로필 수정으로 변경할 수 있으며, 재로그인 때 기존 닉네임을 제공자 값으로 덮어쓰지 않는다.
- **애플 로그인**: Firebase `AppleAuthProvider`와 iOS Runner capability는 구현되어 있다. Apple Developer의 App ID에서 Sign in with Apple을 활성화하고 Firebase Authentication에서 Apple provider를 활성화한 뒤 iOS 실기기에서 확인한다. Apple이 제공하는 익명 이메일은 동일 Apple 계정 식별에 사용하며 일반 이메일 계정과 임의로 연결하지 않는다.
- **약관 동의 UI**: 필수 동의 2종(이용약관/개인정보 수집·이용)은 이메일 스텝 체크박스로 확정됐고, "보기"는 자체 작성 `/legal` 페이지로 연결된다(2026-08-04 QA). 전문 미확정 상태는 해소됨.
