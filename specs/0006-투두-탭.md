> **2026-08-03 리디자인 패치 — 아래 본문 중 충돌 부분은 이 절이 이긴다:**
> - **세그먼티드 컨트롤**은 이제 **[내 투두만]/[전체보기] 한 축**이다(design.md §6 세그먼트 규격, 선택칸 흰 채움+미세 그림자). 기존 **[todo]/[done] 세그먼트 탭은 폐기**.
> - **완료 항목은 done 탭이 아니라 같은 목록에 인라인**(취소선+흐린 텍스트)으로 표시한다. 상단 **⋯ 더보기 메뉴 > "완료된 항목 보기"** 토글로 완료 항목을 숨기거나 다시 표시한다(기본 표시). `full_spec.md` §5의 "완료는 done 탭"과 충돌하나, `full_spec.md`는 보존 원본이므로 여기(파생)를 진실로 삼는다.
> - **"독립 ToDo" 용어를 "기타"로 개명**(사용자 확정). 데이터 개념(`category_id null`)은 동일. `full_spec.md`(보존)·`0002`는 원 용어를 남기되 UI·이 문서는 "기타".
> - **상단 ⋯ 더보기 메뉴**(라우트 아님, 화면 내 오버레이 = 딤 스크림 40% + 우상단 플로팅 카드, design.md §6): ①**항목 선택**(일괄선택 모드) ②**카테고리 관리**(인라인 시트: 추가/이름수정/삭제/순서변경 — `categories.position` + `PATCH /rooms/{roomId}/categories/order` 백엔드 구현 완료, 2026-08-03 . 프론트 드래그 UI는 별도 후속) ③**완료된 항목 보기**(토글) ④**정렬**.
> - **정렬**: **수동/생성일/제목** 3종. **마감일순·담당자순은 없다**(마감일은 데이터상 불가 — 위 "하지 않을 것"·0002). 생성일은 `TodoResponse.createdAt`으로 정렬. **수동은 2026-08-04부터 실제 드래그 순서**(`todos.position`, `PATCH /rooms/{roomId}/todos/order`) — 이전엔 등록순의 별칭이었던 것을 사용자 요청으로 뒤집었다. **드래그는 "내 투두만" 토글 + 정렬 "수동"일 때만 가능**하고, 이동 대상은 **나에게 배정된 투두뿐**이다 — 남의 투두는 자리가 안 바뀐다. FR-39("미지정은 방 멤버 누구나")와는 다르게 미지정 투두는 이 기능의 대상이 아니다("내 투두만" 화면 자체가 미지정을 안 보여주므로, 예외를 두면 화면에 없는 항목을 서버가 자격 있다고 우기는 불일치가 생긴다 — 2026-08-04 리뷰로 발견해 정정). "전체보기"는 드래그 없이 읽기 전용(구현이 단순해지고, 화면에 보이는 게 전부 내 것인 "내 투두만"에서만 조작하면 헷갈릴 일이 없다, 사용자 확정).
> - **일괄선택 모드**: 더보기>항목 선택 진입 → 상단이 선택 툴바(선택 개수/완료처리/삭제/취소)로 바뀌고, 각 행 탭으로 선택 토글. 벌크 완료=담당자 아닌 항목은 서버 403이면 실패 스낵바(FR-39, 아래 데이터 절), 벌크 삭제=확인 모달.
> - **추가 진입**: 상단 "＋"·"＋카테고리" 버튼 제거. 투두 추가는 **리스트 하단 점선 원 어포던스**(또는 빈 상태 "투두 추가") → 기존 [직접추가]/[AI추천추가] chooser. 카테고리 추가는 더보기>카테고리 관리(또는 빈 상태 "카테고리 추가").

> **2026-08-04 UI/UX 개편 (S-15 투두 탭) — 아래 본문·위 2026-08-03 패치 중 충돌 부분은 이 절이 이긴다:**
> - **행 상호작용 변경**: 투두 행은 **전체 영역 단일 탭 = 완료 토글**(체크박스만이 아니라 행 전체), **롱프레스 = 상세/수정 시트(S-18)**. (기존 "체크박스 탭=완료, 텍스트영역 탭=S-18" 폐기.) **좌측 스와이프 = 즉시 삭제**(확인 모달 없이 낙관적 삭제, 서버 실패 시 복원 — `specs/OPEN.md` 사용자 확정 참고. 편집시트/일괄삭제는 확인 모달 유지).
> - **추가/AI 분리**: [직접추가]/[AI추천추가] **chooser 폐기**. 점선 원 어포던스 = **투두 추가 폼 직결**(해당 카테고리로 프리셀렉트). AI추천은 화면 하단 **플로팅 'AI로 생성하기' 버튼**으로 분리 → AI 시트. 점선 원 어포던스는 **각 카테고리·기타 섹션 하단마다** 붙고, 투두가 없어도(빈 상태 포함) 항상 노출된다.
> - **"기타" 섹션은 회색 라벨로 항상 맨 아래**, 카테고리·투두가 하나도 없어도 노출된다.
> - **수동 정렬 시 드래그 재정렬**: 정렬이 "수동"일 때 우측 **드래그 핸들**로 순서를 바꾼다(롱프레스=편집이라 핸들로만). 다른 카테고리/기타 헤더 아래로 드롭하면 **카테고리 이동**(= `category_id` 변경, 서버 저장). **투두 순서(position) 필드는 백엔드에 없어** 같은 목록 내 순서는 **기기 로컬**(`shared_preferences`, `TodoOrderStore`)에만 저장한다(기기 간 동기화 없음). 전체를 하나의 flat `ReorderableListView`로 렌더(헤더=비드래그). **알려진 제약**: 바깥 스크롤 뷰 안에 중첩돼 드래그 중 화면 밖 카테고리로의 자동 스크롤은 되지 않는다.
> - **바텀시트**: 추가/수정/AI/미지정 시트는 `useRootNavigator: true`로 **하단 네비(GNB) 위**에 뜬다. 저장/변경 없이 닫으면 목록을 **리로드하지 않는다**(불필요한 재조회 방지). 폼의 추가/저장 버튼은 **하단 full-width 고정(바닥 24px)**, 담당자 행은 [선택 원 + 프로필 사진 + 이름].

> **2026-08-04 QA 반영 (S-15 행/스와이프 — 위 개편 중 충돌 부분은 이 절이 이긴다, 사용자 확정):**
> - **행 제스처 확정**(위 :19·:22의 "롱프레스=수정 시트", "우측 드래그 핸들"은 폐기됨 — 구현 기준으로 이 줄이 이긴다): **단일 탭 = 완료 토글**, **더블탭 = 상세/수정 시트(S-18)**, **롱프레스 = 드래그 재정렬 시작**(수동 정렬일 때. 드래그 핸들 아이콘은 없고 행 전체를 꾹 눌러 옮긴다), **좌측 스와이프 = 액션 버튼**. 단일 탭은 더블탭 판정(≈300ms) 뒤에 실행된다 — 즉시 반응이 필요하면 제스처 재배치가 필요하다(`specs/OPEN.md`).
> - **스와이프 액션 버튼**: 좌측 스와이프로 드러나는 버튼은 **50×28, 사이 간격 4px**. **투두 행 = [수정][삭제]**, **카테고리 헤더 = [삭제]만**(이름 수정은 헤더 롱프레스 메뉴 유지). 투두는 끝까지 당기면 그대로 삭제(확인 모달 없음, 낙관적)지만, **카테고리는 전체 스와이프로 삭제되지 않는다** — [삭제] 버튼 → 확인 모달을 거친다. "기타"는 실제 카테고리가 아니라 스와이프 액션이 없다.
> - **열린 액션은 화면에 하나만**: 다른 행을 슬라이드하거나 다른 곳(투두 행·카테고리 헤더·＋·세그먼트·더보기·AI 버튼)을 탭하거나 **목록을 스크롤하면** 열려 있던 액션은 **되돌아가고, 탭한 동작은 그대로 실행**된다(닫기만 하고 탭을 먹지 않는다). 열린 행 **자신**을 탭해도 같다 — 닫히면서 완료 토글까지 실행된다.
> - **행 박스 좌우 20px 여백**: 헤더/투두/추가 행의 박스가 좌우 20px 안쪽에 있고, **눌림(pressed) 배경색도 그 박스 안에서만** 보인다(화면 끝까지 번지지 않음). 콘텐츠 x는 32(=20+12) 유지.
> - **슬라이드 중 행 배경은 투명**: 눌림 배경은 `InkWell` 리플이 아니라 직접 그리는 배경이라, 수평 슬라이드로 넘어가는 순간 사라진다.
> - **카테고리 헤더가 투두 행보다 높다**(헤더 48 / 투두·추가 44).

> **2026-08-05 UX 개선 (S-15, 사용자 확정):**
> - **완료 체크는 화면만 즉시, 서버는 2초 뒤**(design.md §8): 2초 안에 같은 항목을 다시 누르면 취소(서버 호출 없음). 화면을 떠나거나 탭을 옮기면 즉시 반영. **'완료된 항목 보기'가 꺼져 있어도 그 2초 동안은 행을 숨기지 않는다** — 숨기면 되돌릴 대상이 없어진다. 공용 구현은 `features/todos/pending_completion.dart`(홈 S-04와 동일 규칙).
> - **탭을 다시 켜면 조용히 재조회**(전체 스피너 없음). 전체 스피너는 첫 로드에만 쓴다 — 투두를 추가하면 기존 목록이 그대로 있다가 결과가 오면 항목이 하나 늘어난다.
> - **바텀시트는 전부 `useRootNavigator: true`** — 더보기·정렬·카테고리 관리 시트도 하단 네비 위에 뜬다.
>
> - **전체보기에는 수동 정렬이 없다**(2026-08-05 사용자 확정): 정렬 시트는 세그먼트에 따라 달라진다 — "내 투두만" = 수동/생성일/제목, **"전체보기" = 생성일/제목**. 수동은 내 투두 드래그 순서라 남의 투두가 섞인 목록에서는 의미가 없고 저장할 곳도 없다. 수동이 걸린 채 전체보기로 넘어가면 **생성일로 대신 적용**하되 고른 값은 그대로 남겨, "내 투두만"으로 돌아오면 수동 순서가 되살아난다(구현: `_availableSorts`/`_effectiveSort`).
> - **수동 정렬의 저장 위치 = 기기 로컬**(2026-08-05 dev 병합 시 사용자 확정 — 위 :14의 "수동은 `todos.position`에 저장되는 실제 드래그 순서"는 **서버 기준**으로만 참이다): 앱은 dev의 카테고리별 드래그핸들 UI 대신 **flat 드래그**(카테고리를 넘나드는 롱프레스 드래그, 핸들 없음)를 쓰고, 같은 목록 안 순서는 `TodoOrderStore`(`shared_preferences`)에만 저장한다 — **`PATCH /rooms/{roomId}/todos/order`는 서버에 있지만 앱이 아직 호출하지 않는다**(기기 간 순서 동기화 없음). 배선은 후속(`specs/OPEN.md`).

## 상단 필터 구성 (S-15, 신규 반영)
`full_spec.md` §5 / 구 `design_full_spec.md` S-15 원본에는 있었지만 기존 0006과 구현에는 누락돼 있던 두 축.

1. **[todo] / [done] 세그먼트 탭**: `todo` = `completed == false`만, `done` = `completed == true`만. 완료 처리된 항목은 todo 탭에서 사라지고 done 탭으로 이동한다(별도 필터 없이 세그먼트로만 구분).
2. **[내 투두만] / [전체 보기] 토글**: 기본값은 **내 투두만**(`todo_assignees.user_id = 나`인 항목만, 기타 포함). "전체 보기"를 켜면 방 전체 투두를 담당자 아바타로 구분해 보여준다. 두 세그먼트(todo/done) 모두에 이 토글이 적용된다. 서버는 이미 방 전체 목록을 반환하므로(TodoController `GET /rooms/{roomId}/todos`) 이 필터는 **클라이언트 사이드**로 처리하고 서버 API 변경은 필요 없다.
3. 카테고리 카드는 기본 펼침 상태이며 헤더의 화살표로 접고 펼 수 있다(순수 UI 상태, 서버 저장 안 함).

## 데이터 (엔티티 연결)
- **categories**: `room_id`, `name` — S-15 인라인 생성/수정/삭제. 삭제 시 하위 `todos.category_id`는 `ON DELETE SET NULL`(0002 확정)로 자동으로 기타가 됨 — 서버가 별도 재배치 로직을 만들 필요 없음.
- **todos**: `room_id`, `category_id`(nullable=기타), `title`(필수), `detail`(선택), `due_date`(nullable), `completed`, `completed_at`, `position`(`V12`, 드래그 순서변경), `created_at` — S-16 생성, S-18 수정/삭제. 정렬은 현재 `position`이며, `due_date`는 알림/정렬을 자동으로 바꾸지 않는다(협업 캐릭터의 마감 준수율 계산에만 쓰인다).
- **미사용 컬럼/테이블(2026-08-07 롤백)**: V16이 만든 `todos.location`·`todos.flagged`·`todos.image_url`과 `todo_tags` 테이블은 **DB에 남아 있으나 엔티티에 매핑하지 않는다**. 되돌리려면 새 마이그레이션으로 DROP 해야 하고 08-06 이후 저장된 값이 사라지므로 그대로 둔다(`specs/OPEN.md` 후속).
- **todo_assignees**: N:M — S-16(생성 시 다중 선택, **미선택 시 미지정으로 남김**, 2026-08-10 확정) / S-18(수정 시 다중 선택 변경) / S-17(미지정 항목에 담당자 추가). "미지정" 상태(행 0개, 0002)는 **직접추가(S-16)·AI추천(S-16-B) 양쪽에서 발생**한다 — 둘 다 담당자 미선택 시 담당자 0명으로 생성돼 미지정 배너/목록(S-17)에 뜬다. (이전 규칙: 직접추가는 본인 자동 지정 → 2026-08-10 폐기.)
- **미지정 판별**: `todos` 중 `todo_assignees` 행이 0개인 것 — 서버가 카운트/목록 제공(S-15 배너 숫자, S-17 목록).
- **완료 체크 권한(FR-39 — `full_spec.md` 밖의 외부 WBS 문서 식별자, 2026-07-29 보정)**: `PATCH .../todos/{todoId}`(완료 토글)는 담당자가 있는 투두는 **그 담당자만** 가능(방 멤버 전체가 아님) — 아니면 403. 담당자가 0명인 "미지정" 투두는 예외로 방 멤버 누구나 체크 가능(사용자 확정 — 미지정 처리 배너와 별개로 완료 자체를 막을 이유는 없음). `TodoService.setCompleted`. **클라이언트 체크박스도 2026-08-08부터 사전 비활성화**한다(QA): 담당자가 있고 내 userId가 담당에 없으면 체크박스를 회색(`surface-soft` 채움)으로 흐리게 표시하고 탭을 흡수해 완료 시도 자체를 막는다(`TodoCheckbox.enabled`, `_TodoListRow.canComplete`). 미지정·내가 담당·userId 미확정은 활성. 남의 투두는 "전체보기"에서만 보이므로("내 투두만"은 애초에 걸러짐) 이 회색 표시도 전체보기에서 드러난다. **2026-08-09**: 회색 체크박스만으로는 "눌릴 것 같은" 오해가 있어, 전체보기에서 **내가 담당이 아닌 읽기전용 투두는 행 전체를 `Opacity 0.55`로 흐리게** 표시해 내 투두(선명)와 구분한다(탭 상세 열기는 그대로). 그래도 **완료 시도가 서버까지 가서 403이 나는 경우**(예: 벌크 완료, race)에는 여전히 담당자 전용 안내 문구("본인이 담당한 투두만 체크할 수 있어요", 서버 body message 그대로)를 인라인으로 노출하고 낙관적 토글을 롤백한다(일반 실패 문구 "완료 처리에 실패했어요"와 구분, 2026-08-04 ). 홈(S-04)·투두 탭(S-15) 두 화면 모두 `TodoNotAssigneeException`(`todos_api.dart`)으로 이 케이스를 구분한다.

## 성공(인수) 기준
- [ ] S-15 진입 시 [내 투두만] 세그먼트가 기본 선택되고, 완료 항목도 기본 표시된다(인라인 취소선).
- [ ] [전체보기]로 전환하면 방 전체 투두가 담당자 아바타와 함께 보이고, 다시 [내 투두만]으로 돌리면 본인 담당(기타 포함)만 남는다.
- [ ] 카테고리별로 투두가 그룹핑되어 보이고, category_id가 null인 투두는 "기타" 섹션(맨 아래)에 모인다.
- [ ] 카테고리 헤더의 화살표를 탭하면 하위 투두 목록이 펼쳐지거나 접힌다.
- [ ] 각 투두 항목에는 체크박스(design.md §5 규격: 미완료=테두리만, 완료=primary 채움+흰 체크)와 담당자 아바타(복수 시 겹쳐 표시 또는 "+N")가 함께 보인다.
- [ ] "＋카테고리"로 이름을 입력하고 확인하면 새 카테고리가 목록 하단(기타 섹션 위)에 추가된다.
- [ ] 카테고리 헤더에서 이름 수정을 선택하면 즉시 반영되고, 삭제를 선택하면 확인 모달 후 카테고리가 사라지고 하위 투두는 기타로 남는다(데이터 손실 없음).
- [ ] 카테고리/기타 하단 점선 원을 탭하면 **투두 추가 바텀시트**가 GNB 위로 열리고, 제목·상세·카테고리·마감일·담당자를 입력해 저장할 수 있다. 제목만 저장하면 **본인이 자동으로 담당자로 지정된 채** 생성되고, 미지정 배너는 늘어나지 않는다.
- [ ] 마감일은 없음/오늘/내일/이번 주말/직접 선택 칩으로 고른다. 저장된 값은 S-18 전체화면 수정에서 선택된 칩으로 다시 보이고, 변경·제거할 수 있다.
- [ ] 인라인 작성기의 흔적(“기존 입력 방식” 버튼, 위치·태그·중요표시·사진 입력)이 어디에도 남아 있지 않다.
- [ ] 카테고리 이동(드래그)·담당자 지정(S-17)처럼 마감일과 무관한 수정을 해도 저장돼 있던 마감일이 지워지지 않는다(`PUT` 전체 교체 특성).
- [ ] 미지정 투두가 0개면 배너가 보이지 않는다(직접추가만 있는 한 항상 0개).
- [ ] "＋"를 탭하면 [직접추가]/[AI추천추가] 선택이 먼저 뜨고, 직접추가를 고르면 기존 S-16 폼이 그대로 나온다.
- [ ] AI추천추가를 고르면 로딩 문구 후 후보 목록이 뜨고, 로드 실패 시 [다시 시도]로 재호출하며, 후보 0개면 빈 상태 문구가 보인다.
- [ ] 후보의 [추가]를 탭하면 **담당자 미지정으로 즉시 생성**되고("추가됨" 표시) 시트는 열린 채 남아 다른 후보를 이어서 채택할 수 있다. **채택한 후보는 카테고리 미지정(기타)으로 들어간다** — AI 가 카테고리를 정하지 않으므로 생성되는 카테고리가 없다(2026-08-04).
- [ ] AI 채택으로 생긴 미지정 투두는 시트를 닫은 뒤 미지정 배너에 집계된다.
- [ ] 미지정 배너를 탭하면 S-17에 미지정 투두 목록이 뜨고, 각 항목마다 담당자를 지정하면 즉시 목록에서 사라진다(낙관적). 마지막 항목을 처리하면 자동으로 S-15로 돌아간다.
- [ ] S-17 에 **닫기/저장 버튼이 없다**. 제목 우측에 남은 개수 뱃지가 보이고, 담당자를 고를 때마다 그 숫자가 줄어든다. 지정에 실패하면 행이 남고 인라인 안내가 뜬다.
- [ ] S-17 행의 `미지정 ⌃⌄` 를 누르면 **투두 추가와 동일한 담당자 선택 바텀시트**가 뜨고(2026-08-09), 멤버를 골라 '완료'하면 지정된다. 방 멤버를 못 불러온 경우에도 시트가 죽지 않는다. S-17 시트는 최소 높이 450 + 하단 safe-area 여백을 둔다.
- [ ] 체크박스를 탭하면 확인 모달 없이 즉시 완료 처리되고, 완료 항목은 같은 목록에 취소선+흐린 텍스트로 인라인 표시된다(done 탭 폐기). 더보기>"완료된 항목 보기"를 끄면 완료 항목이 숨겨진다.
- [ ] 행의 **제목/메모를 탭하면 바텀시트 없이 그 자리에서 인라인 수정**되고 키보드가 바로 올라온다(2026-08-09). 메모가 없던 투두도 편집 중엔 '메모 추가' 빈 칸이 뜬다. 편집 중에만 우측 `information` 아이콘이 보이고, 누르면 상세 시트가 열린다. **바깥을 탭하면 저장**되며 편집이 닫힌다(제목/메모만 바뀌고 카테고리·담당자·마감일은 보존). 읽기전용(남의) 투두도 인라인 수정할 수 있다. 첨부 사진이 있는 투두는 행 메모 아래에 썸네일(50×40)이 보인다(2026-08-24 #65 — 편집·일괄선택 중엔 숨김). 확대뷰는 미결(`specs/OPEN.md`).
- [ ] 더보기 ⋯ 메뉴에 [항목 선택]/[카테고리 관리]/[완료된 항목 보기]/[정렬]이 보이고, 정렬은 "내 투두만"에서 수동/생성일/제목, **"전체보기"에서는 생성일/제목**만 고를 수 있다(마감일순 없음, 전체보기 수동 없음).
- [ ] [항목 선택]으로 일괄선택 모드에 들어가 여러 항목을 골라 완료처리하거나 삭제(확인 모달)할 수 있다.
- [ ] 투두 항목(텍스트 영역)을 탭하면 전체화면 S-18로 이동하고, 서버 최신값이 채워진 채 제목·상세·카테고리·마감일·담당자를 수정해 저장하면 이전 화면(목록)으로 돌아가고 목록에 반영된다.
- [ ] S-18에는 삭제 버튼이 없다 — 목록 행을 좌측으로 스와이프해 삭제한다(확인 모달 없음, 낙관적).

## 엣지케이스
- **카테고리 삭제 시 하위 투두**: 서버 DB 레벨 `ON DELETE SET NULL`로 자동 기타 전환 — 별도 마이그레이션/서비스 로직 불필요, 확인 모달 문구로만 사용자에게 결과를 안내.
- **담당자 전원이 방을 나간 투두**: 이 스펙 범위 밖(방 나가기 스펙에서 처리). 투두 자체는 남아있고, 결과적으로 담당자 0명이 되면 다음 조회 시 자연히 "미지정"으로 집계된다(별도 배치 불필요, 계산값이므로).
- **카테고리/투두 제목 글자 수**: 명세에 없는 저리스크 기본값 — 카테고리 이름 1~20자, 투두 제목 1~50자, 상세 500자 이내로 클라이언트 검증(0004의 "낮은 리스크 기본값" 선례를 따름).
- **날짜·위치 입력의 의미**: 날짜는 로컬 달력 날짜만 저장하며 시간대/시간은 없다. 위치는 선택 레이블 또는 200자 이내의 사용자가 입력한 텍스트로, GPS 좌표·권한·지오펜싱을 요구하지 않는다.
- **동일 카테고리명 중복**: 허용(고유 제약 없음, 0002에 유니크 제약 언급 없음) — 방 인원이 적은 팀 협업 앱 특성상 굳이 막지 않는다.
- **한 투두에 담당자 다수(3명 이상)**: 아바타는 최대 3개까지 보여주고 나머지는 "+N" 뱃지로 축약(design.md 아바타 컴팩트 28px 재사용).
- **완료된 투두의 담당자/카테고리 변경**: S-18에서 완료 여부와 무관하게 항상 수정 가능(별도 잠금 없음).
- **미지정 배너 숫자와 실제 목록 불일치(동시 편집)**: S-17 진입 시 최신 목록을 재조회하고, 이미 처리된(다른 기기에서 담당자 지정된) 항목은 목록에서 제외된 채로 보여준다(에러 없이 자연스럽게 사라짐).
- **[전체 보기] + [done] 조합**: 방 전체의 완료된 투두를 담당자 아바타와 함께 보여준다. 별도 제약 없음.
