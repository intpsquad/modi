# design.md — 디자인 시스템 (유일한 진실)

*v4 — 2026-07-27. **이 파일이 디자인에 관한 단 하나의 진실이다.** 기존 `specs/design_full_spec.md`(S-00 디자인 시스템 + S-01~S-40 화면 상세)와 `specs/DESIGN-airbnb.md`(Airbnb 디자인 분석)를 이 파일로 통합하고 두 파일은 삭제했다. 화면별 상세(S-xx)는 `specs/0004`~`0013`이, IA 원본은 `specs/full_spec.md`가 이어받는다.*

## 1. 원칙

1. **콘텐츠가 주인공, 컨트롤은 절제.** 화면의 90%는 흰 캔버스 + 잉크 텍스트이고, 강조색은 한두 순간만 등장한다.
2. **화면당 강조색은 `color.primary` 하나.** 경고·위험·소셜 브랜드색은 의미 전용이며 강조 용도로 혼용하지 않는다.
3. **굵기가 아니라 여백과 사진/아이콘이 위계를 만든다.** Display를 800으로 때리지 않는다. 큰 제목도 600이면 충분하다.
4. **모서리는 전부 둥글다.** 하드 코너는 화면 그리드(바디) 외에는 쓰지 않는다.
5. **깊이는 그림자가 아니라 헤어라인·라운드 클리핑에서 온다.** 그림자는 §5의 단일 티어만, 실제로 떠 있는 요소(바텀시트·드롭다운·사진 위 플로팅 뱃지)에만.
6. **명확하고 되돌릴 수 있는 액션.** 가벼운 액션(체크·콕찌르기·좋아요)은 확인 없이 즉시 실행 + 낙관적 업데이트. 되돌리기 어려운 액션(방 나가기·삭제·초대코드 재발급)은 반드시 확인 모달.
7. **진행 상태는 항상 명시.** AI/네트워크 로딩은 스피너 + 짧은 문구.
8. **웹 전용 수치는 그대로 가져오지 않는다.** Airbnb의 1280px 컨테이너·64px 레이팅 숫자·80px 탑네비 같은 데스크톱 웹 수치는 모바일 기준으로 재조정한다(§3 각주 참고).

> **캘린더 휴일 색이 `accent-danger`인 이유**(2026-08-07 사용자 확정): 달력의 빨간 날은 "위험"이 아니라 관행적 표기라
> 의미색과는 결이 다르다. 그럼에도 `primary`(#FF385C)를 쓰지 않은 것은, 월간 그리드에서 **primary가 이미 "오늘"과
> "선택일"이라는 조작 상태를 나타내는 색**이어서 휴일까지 같은 색을 쓰면 셋이 구분되지 않기 때문이다.
> 색 우선순위는 **선택일(`on-primary` on `primary` 원) > 오늘(`primary` 텍스트) > 휴일(`accent-danger`) > 평일(`foreground`)**.
> **토요일에는 색을 주지 않는다.** 구현·판정 표는 `app/lib/features/schedule/korean_holidays.dart`,
> 화면 규칙은 `specs/0009-일정-탭.md`.

### 원칙

- **굵은 800은 없다.** 가장 굵은 것이 `display-dday`/`display-hero`의 700이다.
- **"단 하나의 큰 순간"**: Airbnb가 리스팅 상세의 평점 숫자 하나에만 타이포의 목소리를 몰아주듯, 우리는 **홈 히어로의 D-day 숫자**에 `display-dday`(48px/700)를 몰아준다. 이 크기는 홈 히어로 D-day에서만 쓰고 다른 곳에서 반복하지 않는다(반복하면 효과가 죽는다). 히어로는 커버 이미지/그라데이션 위라 D-day·부가 텍스트·진행률 바를 흰색 계열로 둔다(§6 참고).
- 본문 굵기는 400이 기본. 강조가 필요하면 굵기가 아니라 **색(`foreground` vs `muted`)**과 **여백**으로 만든다.

## 5. 엘리베이션 (그림자)

**티어는 딱 두 개: 평평함(flat), 그리고 단 하나의 그림자.**

- **flat (그림자 없음)** — 화면의 95%. 카드·리스트·섹션·입력창은 전부 그림자 없이 **`color.border` 1px + `radius.card` 클리핑**으로만 구분한다. 캔버스와 카드가 둘 다 흰색이므로 테두리가 유일한 구분 수단이다.
- **float (단일 그림자 티어)** — 실제로 떠 있는 요소에만: 바텀시트, 드롭다운/메뉴, 사진 위 플로팅 뱃지, 하단 고정 CTA 바.
  ```
  0 0 0 1px rgba(0,0,0,0.02),
  0 2px 6px 0 rgba(0,0,0,0.04),
  0 4px 8px 0 rgba(0,0,0,0.10)
  ```
- **navBar (위쪽 그림자)** — 플로팅 하단 네비 전용 예외. `0 -4 12 rgba(0,0,0,0.06)` 위 방향 그림자로 스크롤 콘텐츠와 분리(§6 하단 네비). 코드 `elevation.navBar`.
- **scrim** — `color.scrim` 50% 불투명도. 모달·바텀시트 뒤 배경.

점진적 엘리베이션 단계(1dp/2dp/4dp…)는 만들지 않는다. 그림자가 있거나 없거나(+플로팅 네비의 위쪽 그림자) 셋 중 하나다.

## 6. 컴포넌트 규격

### 버튼

| 컴포넌트 | 규격 |
| --- | --- |
| **Primary** | `color.primary` 배경 + `on-primary` 텍스트, `radius.control`(16px), 높이 48px, 패딩 14×24, 타이포 `button`. **화면당 핵심 액션 1개.** |
| Primary(pressed) | 배경만 `color.primary-active`로. 크기 변형·그림자 변화 없음 |
| Primary(disabled) | 배경 `color.primary-disabled`, 텍스트는 흰색 유지 |
| **Secondary** | `color.surface` 배경 + `color.foreground` 텍스트 + `color.foreground` 1px 테두리, `radius.control`, 높이 48px. Primary와 짝을 이루는 대안 |
| Secondary(disabled) | 테두리 `color.border-strong`, 텍스트 `color.muted-soft` |
| **Tertiary(텍스트)** | 배경·테두리 없음, `color.foreground` 텍스트에 밑줄. "더보기"류 |
| **Danger** | `color.accent-danger` 텍스트 또는 배경. **확인 모달 필수 동반** — 예외: 투두 좌측 스와이프 삭제는 모달 없이 낙관적 삭제(사용자 확정, `specs/0006-투두-탭.md`). 카테고리·자료 삭제는 모달 유지 |
| **스와이프 액션 버튼** | 리스트 행을 좌측 스와이프해 드러나는 50×28 버튼(`radius.small`, 타이포 `caption`+600), 버튼 사이 4px. 히트박스는 행 높이 전체. Danger는 `color.accent-danger`+`on-primary`, 중립은 `color.surface-strong`+텍스트 |
| **Pill CTA** | `color.primary` 배경, `radius.pill`, 패딩 10×20, 타이포 `button` 14px. 카드 안의 보조 CTA(콕찌르기 등) |
| **원형 아이콘 버튼** | `color.surface-strong` 배경, `radius.pill`, 32~40px. 뒤로가기·좋아요 하트 등 |
| **AI 액션 버튼**(`AiSparkleButton`, 2026-08-05) | **60px 흰 원** + 중앙 아이콘 28px(`icon_ai_sparkle`, 디자이너 PNG라 tint 없음) + `elevation.float`. **라벨 없음** — 대신 `semanticLabel`로 스크린리더 이름을 준다. 아이콘·크기를 바꿔 다른 AI 액션에도 쓴다. 첫 사용처: 투두 탭 'AI로 생성하기'(S-16-B) |

모든 탭 가능한 요소의 **실제 터치 영역은 최소 44×44px** — 시각 크기가 32px이어도 히트박스는 44px로 확장한다.

### 표면

- **카드**: `color.surface` 배경 + `color.border` 1px + `radius.card`, 그림자 없음, 내부 패딩 `spacing.base`(넉넉히 쓸 땐 `spacing.lg`).
- **AI 안내 배너**(`AiHintBanner`, 2026-08-05): 높이 **40**, `radius.control`(16), 흰 배경 + **AI 그라데이션 2px 테두리**(`ai-gradient-start`→`ai-gradient-end`, **45°**) + **민트 글로우**(`ai-gradient-start` @35%, blur 10, **offset 0,0** — 사방으로 고르게. 핑크는 쓰지 않는다). 이 글로우는 §5의 float 티어와 별개인 **AI 표식 전용**이라 다른 컴포넌트에 퍼뜨리지 않는다. 좌측 아이콘 20px(기본 `icon_ai_sparkle`) + 간격 8 + 문구(`caption` 13px, 남는 폭을 다 쓰고 한 줄 말줄임), 좌우 패딩 16. **세로 패딩은 지정값 10이 아니라 높이 40이 이긴다** — 10+10+테두리 2 = 42라 20px 아이콘이 안 들어가서, 세로는 가운데 정렬로 두고 여백이 9px씩 잡히게 했다. 그라데이션 테두리는 `Border`로 못 그려 **그라데이션 배경 + 1px 안쪽 흰 면(Material)** 으로 만든다. 문구·아이콘을 바꿔 재사용한다(AI 표식이 필요한 안내 전용 — §2). 사용처: 아카이브 자료 상세 AI 요약. (투두 탭 담당자 미지정 안내는 AI 표식이 아니므로 2026-08-09 아래 `NoticeBanner`로 옮겼다.)
- **주의 안내 배너**(`NoticeBanner`, 2026-08-09 ): [AiHintBanner]와 규격은 같되(높이 40 · `radius.control` · 아이콘 20 · 간격 8 · 문구 `caption` 13px · 가로 패딩 16) **AI 표식이 아닌 일반 안내**용. 흰 배경(`color.surface`) + **연한 회색 테두리**(`color.border` 1px) + **아주 옅은 그림자**(검정 4% 한 층 `0 2 8` — §5 float 티어는 이 배너엔 너무 진해서 이 컴포넌트 전용으로 옅게 둠, 2026-08-09 "완전완전 연하게"). 기본 좌측 아이콘 `icon_warning`(자체 채색, tint 없음). 문구 안 특정 부분(`bold`)만 굵게 그릴 수 있다(예: "MODI"). 첫 사용처: 투두 탭 상단 담당자 미지정 안내.
- **토글(`Switch`, 2026-08-08)**: 전역 `SwitchThemeData`(`theme.dart`). **켜짐은 M3 기본 유지** — `color.primary` 트랙 + 흰 thumb, 테두리 없음. **꺼짐은 커스텀** — 흰 배경(`color.surface`) + `color.border-strong`(#C1C1C1) 2px 테두리, thumb도 같은 `border-strong`이며 **켜짐 흰 thumb와 같은 24dp**. (M3는 꺼짐 thumb를 16dp로 작게 그려서, 비선택 상태에 투명 `thumbIcon`을 넣어 24dp로 키운다.) 리플/오버레이 없음. 사용처: 설정 알림 토글, 투두 추가 시트 '중요'.
- **바텀시트**: `color.surface` 배경, 상단만 `radius.sheet`, §5 float 그림자 + scrim. 임시 작업용(페이지 전환 아님).
- **다이얼로그(확인 모달)**: `color.surface`, `radius.sheet`, float 그림자 + scrim. 파괴적 액션의 확인 버튼은 Danger.
  - **아바타형 확인 모달(초대 참여 S-11, 2026-08-05 )**: 중앙 정렬. 상단 원형 아이콘(`color.primary` @10% 배경 + 의미 아이콘 primary, 예 `groups`), 헤드라인 `title`(중앙), 메타 `body-small`(muted), 하단 균등폭 버튼 2개(취소=`surface-strong`/`foreground`, 확정=`primary`/`on-primary`). 비파괴 확인용.
  - **알림형(단일 확인) 모달(2026-08-05)**: 위 아바타형과 같은 셸에 **버튼 하나("확인", `primary` 전폭)**만. 에러 알림은 원형 아이콘을 `color.accent-danger` @10% 배경 + `accent-danger` 아이콘으로(예: 코드 없음 `search_off`). 사용처: S-11 참여 실패(방 없음·종료된 방·일반 오류) — 인라인 에러 텍스트를 대체.
- **코드 입력(PIN 박스)**: N칸 개별 박스. 각 칸 `color.border-soft` 채움 + `radius.small`, 채워진 칸은 글자 표시, 현재 입력 위치 칸에 `color.primary` 포커스 보더. 보이는 박스 위에 투명 `TextField`를 얹어 입력을 받는다. 사용처: 초대 코드 입력(S-11, 6칸 영문·숫자·자동 대문자).
- **소프트필 입력(토스풍, 2026-08-05 )**: 라벨(`body-small`+w600 `color.muted`) + **테두리 없는 채움 입력**(`color.surface-strong` fill, `radius.control`, placeholder `color.muted-soft`) + **포커스 시 `color.primary` 얇은 보더**(글로우). 큰 여백 + 하단 고정 CTA와 함께 쓴다. 사용처: 방 만들기(S-10). 전역 `InputDecorationTheme`(테두리형)와 별개인 화면 로컬 변형이다.
- **초대 코드 공유 카드(S-10-A, 2026-08-05 )**: `color.surface` + `radius.card` + `color.border` 카드 안에 레이블(`badge`+muted) · 코드(`AppTypography.inviteCode` = Jalnan2 28) · "코드 복사" pill 버튼(`radius.pill`, 배경 `color.surface-soft`, 아이콘+`title`)을 세로로 둔다. 코드 복사는 클립보드 + SnackBar 피드백.
- **외부 공유 아이콘 그룹**: 원형(≈56) 아이콘 3종 가로 배치 + 아래 `caption` 라벨. 카카오톡=`color.kakao`+다크 말풍선 / 인스타=인스타 브랜드 그라데이션+흰 카메라 / 더보기=`color.surface-strong`+`color.foreground` 공유 아이콘. 카카오·인스타는 정식 SDK 전까지 "클립보드 복사 + 앱 딥링크(실패 시 OS 공유 시트 폴백)" 인터림.
- **뱃지/칩**: `radius.pill`, 타이포 `badge`, 패딩 4×10. 기본은 `color.surface` + `color.border`; 상태 뱃지("종료됨")는 `color.surface-soft` + `color.muted`.
  - **AI 태그 칩(모아보기 S-25-A/25-B, 2026-08-02 )**: `color.surface` 배경 + **`color.primary` 테두리 1px + `color.primary` 텍스트**(`#태그`). AI 자동 태깅 결과임을 포인트 컬러로 드러낸다. 편집 모드(S-25-B)는 우측에 작은 닫기(×, 14px, primary). 태그 묶음 앞에 AI 표식 `auto_awesome`(✨, 16px, primary).

### 입력

- **텍스트 입력창**: `color.surface` 배경 + `color.border` 1px + `radius.control`, 높이 48~56px, 패딩 14×12. 라벨은 입력창 **위에** `title`로 쌓는다. 플레이스홀더는 `color.muted`.
  - **상태별 테두리 색은 기본/포커스만 구분한다(2026-08-04)** — 에러·성공에도 테두리 색을 바꾸지 않는다(시각적 소음 최소화, 색 개입을 줄여 하단 약관·CTA로 시선 유도). **상태는 입력창 아래 안내 텍스트로만** 표현한다.
  - **포커스**: 테두리 `color.border-strong`(#C1C1C1) **1px**(기본 #DDDDDD에서 한 톤만 진해짐). 글로우/링 없음. *(구 규정 "2px ink"에서 2026-08-04 변경.)*
  - **에러**: 테두리는 **포커스와 같은 회색(`color.border-strong`) 유지 — 빨강 아님.** 경고는 입력창 아래 인라인 텍스트(`body-small`, `color.accent-danger`)로만.
  - **성공/완료**: 테두리 회색 유지, **안내 텍스트 없음**(성공 문구를 띄우지 않는다 — 색 개입 최소화). *(구 규정의 `accent-success` 파랑 성공 테두리·"사용할 수 있는 이메일이에요"류 문구는 폐지.)*
  - **빈 필수값(2026-08-04)**: 빈 필드는 에러가 아니라 **기본 상태**로 둔다 — "○○를 입력해 주세요" 문구를 띄우지 않고, **CTA 비활성**으로 알린다(폼 CTA는 필수값이 채워질 때만 활성). 형식오류·불일치 등 **실제 규칙 위반(값이 있는데 틀림)일 때만** 빨간 인라인 안내를 보여준다. 요즘 모바일 폼 트렌드.
  - **비활성**: 배경 `color.surface-soft`, 텍스트 `color.muted-soft`.

- **시간 선택 휠 시트(2026-08-31, #80)**: 시각을 고르는 유일한 수단. **바텀시트 + 휠 3개 + 하단 고정 CTA `완료`** 구성이며, 시트 규격은 §6 바텀시트를 그대로 따른다(그리퍼 · 제목 `section` "시간 선택" · CTA 바닥 고정). 구현 `app/lib/design/time_wheel_sheet.dart`(`showTimeWheelSheet`).
  - **휠 3개**: 시(1~12) / 분(**1분 단위** 00~59) / **오전·오후**. 라벨은 `title`(16/600) `color.foreground`.
  - **`AM`/`PM`이 아니라 「오전」/「오후」로 적는다** — 고른 뒤 화면에 보이는 값이 `formatTimeOfDayKorean`의 "오전 9:00"이라, 고르는 순간과 고른 뒤의 말이 갈리면 안 된다.
  - **선택 칸 표시**: 가운데 한 칸에 `color.surface-soft` 배경 + `radius.small`. 테두리·그림자 없음.
  - **휠 한 칸 높이 44 / 휠 전체 높이 220(44×5)** — §4 스페이싱 스케일 밖의 값이다. 글자가 잘리지 않을 최소 높이가 4px 스케일로 잡히지 않아 이 컴포넌트에만 둔다(최소 터치 영역 44와 같은 값).
  - **취소 버튼이 없다** — scrim 탭·스와이프로 닫으면 `null`이 돌아오고 호출부가 기존 값을 지킨다. CTA는 §7 Primary 하나뿐이라는 시트 규격과도 맞는다.
  - **선택 칸을 더블탭하면 숫자를 직접 친다**(시·분만 — 오전·오후는 숫자가 아니라 대상이 아니다). 휠로 60칸을 굴리는 것보다 빠른 경우가 있고, 대체 전 Material `showTimePicker`에 있던 키보드 입력 경로를 이것이 대신한다.
    - **회색 선택 칸 위에서 글자만 바뀐다** — 흰 배경·테두리를 덧대지 않는다. 전역 `inputDecorationTheme`이 `filled: true`(흰색) + 테두리를 입히므로 **`border`만 끄면 안 되고** `filled`와 테두리 6종을 모두 꺼야 한다.
    - 입력창 높이를 칸 높이(44)로 **고정하지 않는다** — 고정하면 위쪽 정렬이 되어 더블탭하는 순간 숫자가 제자리에서 위로 튄다.
    - **범위를 넘는 값은 거부하지 않고 잘라 맞춘다**(13시 → 12시, 99분 → 59분). 입력을 막으면 왜 안 먹는지 알 수 없어 더 답답하다. 빈 값·숫자가 아니면 기존 값을 지킨다.
    - **휠 바깥 어디든 터치하면 키보드가 내려가고 값이 확정된다**(`TextField.onTapOutside`). 필드 안쪽 탭은 걸리지 않는다.
  - ⚠️ **구현 함정 둘** — 둘 다 위젯 테스트로는 안 잡히거나 잡기 어려워 실기 확인에서 나왔다.
    - 선택 칸 배경을 `CupertinoPicker.selectionOverlay`로 넘기면 **자식 위에** 그려져 고른 값을 통째로 가린다. 배경은 피커 **뒤**(`Stack`)에 깔고 `selectionOverlay`는 비운다.
    - 편집 중에는 피커 자리에 입력창이 있어 스크롤 컨트롤러가 **detach 상태**다. `jumpToItem`이 먹지 않고 피커가 다시 그려질 때 생성 시점 값으로 되돌아가므로, **컨트롤러를 새로 만들어 끼운다**.
  - 사용처: 일정 생성·수정 시트의 **시간·종료 두 행**(`specs/0009-일정-탭.md`). 날짜는 여전히 `showDateRangePicker`다.

### 프로젝트 고유 컴포넌트

- **하단 네비(플로팅)**: `color.surface` 배경, **상단 좌우만 `radius.navBar`(24px)** 라운드(하단 0), **위쪽 은은한 그림자**(`elevation.navBar` = `0 -4 12 @ 6%`)로 스크롤 콘텐츠와 분리된 플로팅 느낌. **5탭(홈/투두/일정/모아보기/마이)** 가로 균등 배치, 각 칸 아이콘 위·라벨 아래 수직 정렬(2026-08-06: 마이페이지 탭이 맨 오른쪽에 추가됐다 — `specs/0003-navigation.md`). **아이콘은 단색 SVG 5종**(`assets/icons/nav_{home,todo,schedule,archive,my}.svg`, `flutter_svg`, 24px)을 상태별로 **틴트**한다 — 활성 `color.primary` / 비활성 `color.muted`(`ColorFilter.mode(..., srcIn)`). *2026-08-07: 크기·해상도가 제각각(마이만 48px·@2x/@3x 없음)이던 PNG 10종을 광학 크기·스트로크(1.5px)를 통일한 SVG 5종으로 교체 — 해상도 무관·색 일관.* 라벨은 활성 `color.primary`+굵기 600 / 비활성 `color.muted`+400. **인디케이터 pill 없음, 눌림(press) 오버레이 색도 없음**(`navigationBarTheme.overlayColor = transparent`) — 선택은 아이콘 active/inactive와 라벨 색·굵기로만 구분.
- **코치마크(스포트라이트)**: 숨은 제스처를 최초 1회 가르칠 때만 쓴다(현재 사용처 = 하단 네비 홈 버튼 롱프레스 → S-07, `specs/0008-방-전환.md`). 전면 `color.scrim` dim + 대상 위치만 원형으로 뚫고(반지름 28~34px) 테두리 링 `color.primary` 2px. 말풍선은 `color.canvas` + `radius.card` + `elevation.float`, 안쪽 여백 `spacing.base`, 제목 `title` + 보조 `body-small`, 아래쪽 꼬리(16×8px)가 대상을 가리킨다. **대상 위에서 실제 제스처를 하게 만들고**(설명만 읽히지 않게), 바깥 탭으로 닫힌다. 노출 횟수는 기능별로 정하되 반드시 유한해야 하고, 사용자가 그 제스처를 한 번이라도 성공하면 영구 미노출. 반짝임(펄스) duration은 모션 토큰이 없어 임시값이다 — `specs/OPEN.md` 참고.

## 8. 인터랙션 원칙

- **즉시 실행(확인 없음)**: 콕찌르기, 재촉, 좋아요 → 낙관적 업데이트 후 서버 반영.
- **투두 완료 체크는 화면만 즉시, 서버는 2초 뒤**(2026-08-05 사용자 확정): 잘못 눌렀을 때 되돌릴 시간을 준다 — 2초 안에 같은 항목을 다시 누르면 없던 일이 된다(서버 호출 없음). 화면을 떠나거나 탭을 옮기면 대기 중인 것은 **즉시 반영**한다(버리면 체크가 사라져 보인다). 그 2초 동안 그 행은 **목록에서 빼거나 숨기지 않는다** — 되돌릴 대상이 없어지기 때문. 홈·투두 탭이 같은 규칙을 쓴다(`features/todos/pending_completion.dart`).
- **재조회에 전체 스피너를 쓰지 않는다**: 스피너는 **첫 로드에만**. 한 번 내용을 보여준 화면은 재조회(탭 재진입·당겨서 새로고침·추가/수정 후 갱신) 중에도 그대로 두고, 결과가 오면 내용만 갈아끼운다.
- **바텀시트는 항상 최상단**: `showModalBottomSheet(useRootNavigator: true)` — 그러지 않으면 플로팅 하단 네비가 시트 위로 올라온다.
- **탭 전환은 옆으로 미끄러진다**(220ms, `easeOutCubic`): 오른쪽 탭으로 가면 새 화면이 오른쪽에서 들어오고 이전 화면은 왼쪽으로 빠진다. 탭을 다시 켜면 그 화면은 **이전에 받아둔 내용을 그대로 보여준 채 조용히**(스피너 없이) 최신 상태로 갱신한다 — 빈 화면이나 스피너를 거치지 않는다.
- **하위 페이지는 오른쪽에서 들어오고, 왼쪽 끝을 끌면 돌아간다**(2026-08-05 확정): 탭이 아닌 모든 화면(상세·설정 등)은 ① 오른쪽에서 왼쪽으로 밀려 들어오고, ② 화면 **왼쪽 끝**을 잡고 오른쪽으로 끌면 이전 화면이 드러나며 뒤로 가고, ③ 뒤로가기 아이콘은 `←`가 아니라 **`<`**(chevron, 28px), ④ **하단 네비바가 보이지 않는다**(탭이 아니라 새 페이지다). 규칙과 구현 위치는 `specs/0003-navigation.md` "하위 페이지 규칙" 표가 단일 진실.
- **확인 모달 필수**: 방 나가기(마지막 멤버면 방 삭제 안내 동반), 자료 삭제, 초대코드 재발급(기존 코드 즉시 무효화 안내).
- **AI 로딩**: 진행 상태 명시 후 결과 노출.
- **호버 상태는 정의하지 않는다** — 모바일 전용이므로 pressed/disabled만 정의한다.
- **리스트 행 pressed**: 행 박스에 `color.surface-strong` 배경 + `radius.control`. 박스는 화면 좌우 여백 안쪽에 있어야 하며(눌림 색이 화면 끝까지 번지면 안 된다), **좌우 스와이프로 넘어가는 순간 즉시 투명으로 돌아간다**(Material 리플은 슬라이드 중에도 남아 배경처럼 보이므로 쓰지 않는다).
- **열린 스와이프 액션은 화면에 하나만**: 다른 행을 스와이프하거나 다른 곳을 탭·스크롤하면 열려 있던 액션은 닫히고, **탭한 동작은 그대로 실행**된다(닫기만 하고 탭을 먹지 않는다).

## 9. 확정 사항

- **다크모드**: 라이트만 (MVP 확정). Airbnb 공개 웹도 다크모드가 없다.
- **폰트**: **Pretendard** 앱 전역 번들 확정(2026-08-01, SIL OFL). 정적 4종 Regular/Medium/SemiBold/Bold. §3 참고.
- **접근성**:
  - 최소 탭 영역 44×44px (시각 크기와 무관하게 히트박스로 보장).
  - 텍스트 대비 WCAG AA 이상 — `color.foreground`(#222222) on `color.canvas`(#FFFFFF)는 15.9:1로 AAA 통과. `color.muted`(#6A6A6A) on 흰 배경은 5.7:1로 AA 통과(본문 크기까지 사용 가능), `color.muted-soft`(#929292)는 3.5:1로 **비활성 텍스트에만** 사용.
  - `color.primary`(#FF385C) on 흰 배경은 3.9:1 — **큰 텍스트/아이콘/면 채움에만** 쓰고 본문 크기 텍스트 색으로는 쓰지 않는다. Primary 버튼은 흰 텍스트 on #FF385C(4.0:1)로 대비를 확보한다.
  - 큰글씨 접근성 설정 시 `body` 이하 텍스트가 레이아웃을 깨지 않도록 `Flexible`/줄바꿈 허용.
