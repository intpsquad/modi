# 0004 — 방 생성/참여

> 관련 스펙: `specs/0003-navigation.md`(S-03/S-06/S-10/S-10-A/S-11 라우트·전이), `specs/0002-data-model.md`(rooms/room_members/invite_codes→Redis), `specs/design.md`(버튼·확인 모달·상태 패턴).

## 목적
로그인한 사용자가 방을 만들거나 초대코드로 기존 방에 참여해 셸(홈)에 진입하게 한다. 방 소속이 0개인 사용자는 이 흐름을 **스킵할 수 없다**(온보딩 게이트). 이후 진행 중(ACTIVE)인 방이 하나도 없는 상태(S-06)에서도 같은 화면들을 재사용해 추가로 방을 만들거나 참여할 수 있다.

## 하지 않을 것
- 방장 개념/권한 차등 — 생성자든 참여자든 `room_members` 상 동일 권한.
- 초대코드 발급 이력·과거 코드 조회 — Redis TTL(1일)로 자동 소멸, 재발급 시 이전 코드는 즉시 무효화되고 이력을 남기지 않는다.
- 링크만으로 참여를 확정하는 동작 — 카카오 초대 링크는 S-11에 코드를 **미리 채우기만** 하고, 사용자가 방 미리보기 확인 모달에서 참여를 확정한다.
- 방 나가기/삭제/재시작 플로우 — 별도 스펙(S-40-B/C, S-12).
- 방 생성 시 기본 카테고리 자동 생성 — `categories`는 선택 그룹이라 방 생성 시점엔 만들지 않는다(사용자가 `/todos`에서 필요할 때 생성).

## 데이터(엔티티 연결)
- **rooms**: `name`(필수), `goal`(필수), `goal_detail`(선택), `start_date`/`end_date`(필수, `start_date <= end_date`), `cover_image`(선택) — S-10 입력값. `status`는 생성 시 `ACTIVE` 고정.
  - **대표 이미지 업로드**: 방 생성 화면에서 갤러리/카메라로 대표 이미지를 선택·업로드할 수 있다. **2단계** — 파일을 `POST /rooms/cover-image`(multipart)로 올려 URL을 받고, 그 URL을 `POST /rooms`의 `coverImage`로 전달. 계약: `docs/api/room-cover-image.md`. 구현: `app/lib/features/room/room_cover_image_field.dart`.
- **room_members**: 생성 성공 시 생성자 본인 row를 즉시 추가(`joined_at = now`) — 방장이 없으므로 생성자도 그냥 첫 멤버.
- **invite_codes → Redis** (Postgres 테이블 아님, `specs/0002-data-model.md` 참고):
  - 방 생성 성공 시 6자 코드 발급: 혼동 문자(`0`/`O`, `1`/`I`) 제외 32자 알파벳에서 랜덤, `invite:code:{CODE}` → `roomId` / `invite:room:{roomId}` → `CODE`, 둘 다 TTL 86400s.
  - S-11에서 코드 조회는 `invite:code:{CODE}` GET → 없으면(만료/오타) 무효 처리.
  - 참여 성공 시 `room_members`에 row 추가(이미 멤버면 idempotent, 아래 엣지케이스 참고).
  - **미리보기 응답(→ 2026-08-07 로 구현 완료)**: 참여 확인 모달의 "멤버 N명 · 기간" 표기용으로 `GET /invite-codes/{code}` 응답에 `memberCount`(int)·`startDate`/`endDate`(ISO date)가 추가됐다. `RoomService.previewInvite`가 이미 로드해 둔 `Room` 엔티티와 기존 `RoomMemberRepository.countByRoomId`를 그대로 재사용해 채운다 — 새 쿼리·컬럼 없음.

## S-03 화면(UI) — 방 없음 허브
- 중앙 정렬 히어로. 원형 그래픽(Ø 88, `surface-strong` + `card_giftcard` primary 40) + 타이틀(`display`) + 서브(`body-small`+`muted-soft`) + Primary "방 만들기"(풀폭, 테마 버튼) + Secondary "초대코드로 참여하기"(고스트 `TextButton`, `foreground`/w600, 밑줄 없음). `PopScope(canPop:false)`.
- **조건부 타이틀**: 방을 한 번이라도 가진 적 있으면(SharedPreferences `last_viewed_room_id` 존재 — 생성/참여 시 기록, 방 다 나가도 남고 `clear()`에서만 삭제) **"현재 진행 중인 방이 없어요!"**, 완전 신규면 **"첫 번째 방을 만들어볼까요?"**. 구현 `RoomSession.hasEverEnteredRoom()`.

## S-06 화면(UI) — 홈의 방없음 상태
S-03과 **같은 히어로를 공유한다**(`app/lib/features/room/no_room_hero.dart`, 2026-08-16 추출). 원형 그래픽·타이포·서브 문구·CTA 2개가 전부 동일하고, 다른 것은 **바깥 두 가지뿐**이다.

| | S-03 (온보딩 게이트) | S-06 (홈) |
|---|---|---|
| 라우트 | `/onboarding/room-setup` | `/home` — 방 상태로 분기 |
| 도달 조건 | `membership == none` (방 0개) | `membership == has` + ACTIVE 방 0개 (= 종료된 방만 가짐) |
| 뒤로가기 | `PopScope` — 신규는 차단, returning은 허용 | **없음**(일반 네비게이션) |
| 타이틀 | 조건부 — `hasEverEnteredRoom()` | **항상 "현재 진행 중인 방이 없어요!"** |

- **타이틀이 고정인 이유**: 라우터가 방 0개를 S-03으로 보내므로(`app_router.dart`), `/home`에 도달했다는 것 자체가 "방을 가지고 있다"는 뜻이다. S-03이 쓰는 `hasEverEnteredRoom()`은 SharedPreferences(`last_viewed_room_id`) 기반이라 **기기를 갈아타면 false**가 되어 S-06에서 쓰면 "첫 번째 방을 만들어볼까요?"가 잘못 뜬다.
- **상단 바 없음**: 히어로가 히어로 상단 바(방이름▾)보다 먼저 return 된다 — S-06에는 방 전환 트리거가 없다(`specs/0008-방-전환.md`).
- **분기 신호는 `_roomId`**: `home_screen.dart`의 `_load()`는 진행 중인 방이 없을 때만 `_roomId`를 null로 둔다. ~~`_data == null`~~로 가르면 방이 **있는데** 대시보드만 못 채운 경우까지 "방이 없어요"라고 잘못 말한다(2026-08-16 정정).
- **CTA는 2개뿐이다**: 종료된 방은 마이 탭 → 지난 방 보기(`/mypage/past-rooms`)로 이미 갈 수 있어 막다른 길이 아니다. "지난 방 보기"를 세 번째 CTA로 두는 안은 검토 후 **채택하지 않았다**(2026-08-16 사용자 확정, `full_spec.md:255` "CTA 2개").
- **복귀**: 두 CTA로 방을 만들거나 참여하면 `markHasRooms()` → `switchRoom(roomId)` → `go('/home')`를 거치고, `switchRoom`의 `notifyListeners()`를 홈이 듣고 있어 S-04로 자동 전환된다(`invite_share_screen.dart` / `join_room_screen.dart`).

## S-11 화면(UI) — 초대 코드 입력
- **입력**: 6칸 코드 박스(PIN형). 각 칸 `color.border-soft`(#EBEBEB) 채움 + `radius.small`(8), 현재 입력 위치 칸에 `color.primary` 포커스 보더. 영문·숫자만, 소문자는 자동 대문자. 카카오 실행 URL의 유효한 6자리 코드는 대문자로 정규화해 처음부터 채운다. 헤더는 열쇠 아이콘(primary) + `display`(22/600) 타이틀 + `body`(muted) 안내.
- **CTA**: 하단 고정 "참여하기". 6칸 완입 전 비활성(`primary-disabled`), 완입 시 `color.primary` 활성. 검증 중 스피너.
- **확인 모달**: 중앙 정렬 다이얼로그(`radius.sheet` 20 + scrim). 상단 원형 아이콘(primary @10% 배경 + `groups` primary), 헤드라인 "{방 이름}에 참여하시겠습니까?"(`title` 16/600, 중앙), 메타 "멤버 N명 · yyyy.MM.dd – yyyy.MM.dd"(`body-small` muted; 시작·종료 모두 풀 연도. 멤버 수·기간은 preview API의 `memberCount`/`startDate`/`endDate`로 채운다, 2026-08-07 ). 버튼 2개: 취소(`surface-strong`/`foreground`) · 참여하기(`primary`/`on-primary`). 파괴적 아님 → Danger 아님.

## S-10-A 화면(UI) — 초대 코드 공유
- **완료 헤더**: `primary` 원 + 흰 체크 그래픽, "방이 만들어졌어요"(`display`) + "초대 코드를 팀원에게 공유하세요"(`body` muted).
- **코드 카드**: `surface`+`radius.card`+`border`. 레이블 "초대 코드"(`badge` muted) · 코드(**Jalnan2** `inviteCode` 28) · "코드 복사" pill(`surface-soft`)=클립보드 복사+SnackBar. 아래 헬퍼 "설정 › 방 멤버 관리에서 언제든 다시 볼 수 있어요"(`caption` mutedSoft).
- **외부로 공유하기**: 원형 아이콘 3종 — 카카오톡(`kakao`)·인스타(브랜드 그라데이션)·더보기(`surface-strong`).
  - **카카오톡**: `kakao_flutter_sdk_share`의 기본 `FeedTemplate`을 전송한다. 카카오톡 안에서 수신 채팅방을 고르면 방 대표 이미지(없으면 앱 기본 커버를 Kakao 이미지 서버에 업로드)·방 이름·**"참여하기"** 버튼이 포함된 카드가 공유된다. 버튼/카드 링크에는 `route=room/join`과 `inviteCode`를 Android/iOS execution parameter로 넣는다. 카카오톡이 없으면 SDK의 Web Sharer URL을 연다.
  - **인스타그램**: 외부 앱이 DM 입력창을 선작성할 수 없으므로 **초대 코드만** 클립보드에 복사한 뒤 `instagram://`으로 전환한다. **2026-08-07**: 탭하면 갑자기 앱이 열려 오류처럼 보이던 걸 개선 — 코드를 먼저 복사하고 **확인 팝업**(입장 확인 모달과 같은 `showAppConfirmDialog` 셸: "초대 코드를 복사했어요. 인스타그램에서 DM에 붙여넣어 보낼 수 있어요." · [취소]/[이동])을 띄운 뒤 **[이동]을 눌러야** 전환한다. 앱 전환 실패 시에도 코드는 남기고 DM에 붙여넣도록 안내. (인스타는 특정 DM 작성+텍스트 프리필 딥링크를 제공하지 않아 이 흐름이 표준.) Stories SDK 카드 공유는 범위 밖.
  - **더보기**: `share_plus`로 iOS/Android의 **OS Native Share Sheet**를 열어 AirDrop·문자·메일·설치 앱 등으로 초대 문구를 공유한다. **2026-08-07**: iOS에서 안 열리던 문제 — `Share.share`에 **`sharePositionOrigin`**(트리거 화면 영역)을 넘겨 팝오버 앵커를 지정한다. `UIActivityViewController.popoverPresentationController`는 iPad뿐 아니라 iPhone에서도 non-nil이라 rect가 비어 있으면(`CGRectZero`) 기기 종류와 무관하게 시트가 안 뜬다 — **2026-08-26**: 이 앵커 계산을 빠뜨린 S-40-B 공유 시트(`invite_share_options.dart`)의 "더보기"가 같은 증상으로 재발해, 두 진입점이 공유하는 `inviteShareOrigin()` 헬퍼(`invite_share.dart`)로 통합했다(#71).
- **CTA**: 하단 고정 "홈으로"(`primary`) → S-04 replace. `PopScope(canPop:false)`로 뒤로가기 차단(온보딩 게이트).

## 성공(인수) 기준
- [ ] 방 소속 0개 사용자는 앱을 재실행해도 셸에 접근하지 못하고 항상 S-03으로 리다이렉트된다.
- [ ] S-10에서 방 이름·목표를 채우면 하단 "만들기"가 활성화되고, 생성하면 `rooms` row와 생성자의 `room_members` row가 만들어지고 S-10-A로 이동해 6자리 코드가 보인다. (**시작일=오늘 자동**, 종료일 기본 오늘+4주·변경 가능.)
- [ ] S-10-A에서 "홈으로"를 탭하면 S-04로 replace 이동하고, 시스템 뒤로가기로 온보딩/생성 화면으로 못 돌아간다.
- [ ] S-10-A/S-40-B의 카카오톡 공유는 채팅방 선택 후 방 썸네일·방 이름·"참여하기" 버튼이 든 FeedTemplate 카드를 전송하며, 버튼을 누른 앱 사용자는 S-11에서 초대 코드가 미리 채워진다.
- [ ] 인스타그램 공유는 코드만 복사한 뒤 앱을 열고, 더보기는 OS Native Share Sheet를 연다.
- [ ] S-11에서 6자를 다 입력하면 "참여하기"가 활성화되고(그 전엔 비활성), 탭하면 방 정보가 담긴 확인 모달이 뜬다. 확인 시 `room_members`에 추가되고 S-04로 replace 이동한다.
- [ ] 존재하지 않거나 만료된 코드는 **알림 팝업**("코드를 찾을 수 없어요")을 띄우고, 닫으면 화면에 머문다(재입력 가능).
- [ ] 종료(`ENDED`)된 방의 코드는 참여할 수 없고 별도 **알림 팝업**("종료된 방이에요")을 띄운다.
- [ ] 이미 소속된 방의 코드를 다시 입력해도 에러 없이 참여 처리되어(중복 삽입 없이) S-04로 이동한다.
- [ ] 종료된 방만 가진 사용자가 홈에 오면 S-03과 **같은 히어로**(원형 그래픽 + "현재 진행 중인 방이 없어요!" + CTA 2개)가 뜨고, 방 전환 트리거(방이름▾)는 보이지 않는다.
- [ ] 그 상태에서 `last_viewed_room_id`가 없어도(기기 교체) "첫 번째 방을 만들어볼까요?"가 뜨지 않는다.

## 상태(로딩·빈·에러)
- S-10 "만들기" 탭 후: 버튼 로딩 스피너 + 중복 탭 방지, 성공 전까지 폼 비활성화.
- S-11 "참여하기" 탭 후: 코드 검증 중 버튼 로딩 스피너.
- 에러(2026-08-05): 실패는 **알림 팝업**(아이콘+제목+메시지+단일 "확인")으로 알린다 — 방 없음 "코드를 찾을 수 없어요" / 종료된 방 "종료된 방이에요" / 일반 오류 "참여하지 못했어요". 인라인 에러 텍스트는 폐지. 코드 형식은 클라이언트에서 즉시 가드 — **6칸이 다 차야 "참여하기"가 활성**되고(미만이면 비활성), 허용 문자(영문·숫자)만 입력되도록 필터.
- 네트워크/서버 오류: 알림 팝업(재시도 유도), 입력값 유지.

## 엣지케이스
- **뒤로가기(시스템 back)**: S-03(게이트)에서는 완전 차단(빠져나갈 이전 화면 없음 — 무동작 또는 앱 종료). S-03을 경유해 도달한 S-10/S-11에서 뒤로가기는 S-03으로만 복귀(게이트 자체는 유지). S-06을 경유한 경우는 일반 네비게이션(홈으로 복귀).
- **코드 입력 대소문자**: 소문자 입력 시 클라이언트에서 자동 대문자 변환.
- **코드 재발급(S-40-B, 별도 스펙)**: 이전 코드의 Redis 키를 즉시 삭제/교체 — 이 스펙에서는 참여 실패 사유("만료됨")로만 영향받음.
- **동시 참여(중복 탭/여러 기기)**: `room_members` PK(`room_id`,`user_id`)로 유일성 보장, 서버는 이미 멤버인 요청을 에러 없이 idempotent 처리.
- **방 생성 필드 검증 상세값**(이름 글자 수 제한 등)은 0002/design에 명시 없음 — 구현 시 낮은 리스크 기본값(예: 이름 1~30자)을 적용하고, 사용자에게 노출되는 제약이 아니면 별도 확인 없이 진행.
