## 목적
ACTIVE 방에 진입한 사용자가 홈(S-04)에서 방의 목표 기간(D-day), 멤버별 진행 현황, 이번 주 일정, 내가 할 일, 최근 아카이브를 한 화면에서 훑어보고 각 상세로 빠르게 이동하게 한다.

## 하지 않을 것
- 종료된 방 요약(S-05), 방 없음 상태(S-06) — 별도 화면(S-05는 PROJECT_PLAN Phase 3, S-06은 `specs/0004-방-생성-참여.md`에서 다룸). 이 스펙은 **`rooms.status = ACTIVE`인 방의 대시보드만** 다룬다.
- 투두/일정/아카이브 CRUD — 각각 S-15~18(투두 탭)/S-20(일정 탭)/S-25(아카이브 탭) 스펙에서. 홈은 미리보기 + 이동만 담당.
- AI 투두 추천(S-16-B) — Phase 3, 이 스펙 범위 밖.
- 주간캘린더에서의 일정 생성/수정 — 사용자 확정: 홈 주간캘린더는 **읽기전용 미리보기**. 생성/수정은 일정 탭(S-20-A/B)에서만.

  - **커버 이미지 노출**(2026-08-01 구현 완료): 대시보드 응답 `room.coverImage`(nullable)에 `rooms.cover_image`(0002) 값을 그대로 실어준다(`RoomInfo.of`). 앱은 이 값을 히어로 배경으로 쓰고, null이면 `color.primary`→`color.primary-active` 그라데이션으로 폴백. 커버 이미지 업로드/설정 플로우는 방 생성·설정에서 별도(이 화면은 표시만) — `docs/api/room-cover-image.md`.
  - **방 전체 진행률**(2026-08-01 구현 완료): 대시보드 응답 `todoDone`/`todoTotal`(방 전체 투두 완료/전체 개수, `DashboardService.getDashboard`가 `TodoRepository.countByRoomIdAndCompletedTrue`/`countByRoomId`로 방 단위 직접 집계) — 히어로 진행률 바와 "함께 달성한 투두"(+우측 %)에 사용. 멤버 진행률과 같은 **계산값**(저장 안 함)이며, 멤버별 `assignedTotal` 합산과 달리 다중 담당자 투두를 중복 집계하지 않는다. 앱의 멤버 담당 합산 근사치 폴백은 그대로 유지 — 이 필드가 오면 자동 교체.
- **멤버 아바타줄**: `room_members` (해당 room_id) → 각 멤버의 **개인 진행률** = 본인 담당 완료 todos / 본인 담당 전체 todos (0002 "계산값" 정의, 저장 안 함·요청 시 계산). **정렬은 개인 진행률 내림차순(진행률 높은 순 좌→우)** — `full_spec.md` §3-2-2 / 구 `design_full_spec.md` S-04 원본 반영(2026-07-27, 기존 `joined_at` 오름차순에서 교정). **동률(같은 %) 처리: ① 완료 개수(assignedDone) 많은 순 → ② 그래도 같으면 서버가 준 순서(가입순, 원본 인덱스)** — Dart `sort`가 안정성을 보장하지 않아 원본 인덱스를 마지막 키로 써 결과를 결정적으로 고정한다(2026-08-08 QA). **순위 메달**(등수 ≤ 3 **이면서 진행률 > 0**인 멤버에만 — 0%(완료 0개)는 상위 등수여도 제외, 2026-08-08 사용자 확정: 전원 0%인데 다 금메달 되는 걸 막음. 금·은·동, 아바타 우상단 — 사용자 제공 SVG 아트 `assets/icons/icon_badge_medal_{gold,silver,bronze}.svg` 23×30, `flutter_svg`. 메달 아트에 왕관·순위 숫자가 포함돼 코드로 색·번호를 그리지 않는다), **본인은 이름을 "닉네임(나)"로 굵게** 표기해 자기 찾기를 돕는다(위치 고정 대신 메달로 순위 명시, 2026-08-08 QA — 순수 순위 vs 나 고정 논의 끝에 "메달을 넣으면 순수 순위가 깔끔"으로 확정). 구현 `_RankBadge`(`home_screen.dart`).
- **주간캘린더**: `schedules` (해당 room_id, 이번 주 `date` 범위, 월요일 시작). **일정만 연동, 투두 연동 안 함**(0002 §schedules 명시 재확인). 일정 있는 날은 하단 상태 점으로 표시하고, **선택된 날짜의 일정은 달력 하단에 일정 카드 리스트**(흰+8px+좌측 액센트 바 4px, 제목·시간, 읽기전용)로 노출한다(상태 점과 같은 데이터·색). 날짜 셀은 탭하면 Active 하이라이트가 이동하지만(기본 선택=오늘) 화면 전이·시트는 없다(**읽기전용**, 로컬 상태만). 액센트 바를 카테고리별 색으로 구분하려면 일정에 category/color 필드 필요(현재 `ScheduleBrief`에 없어 primary 단일) — `specs/OPEN.md` 미결. 상태 점을 "투두 작성/출석 여부"로 확장하는 것도 백엔드 날짜별 플래그 필요 — 동 미결.
- **오늘투두**: 사용자 확정 — **내 담당 미완료 투두만**. 쿼리: `todo_assignees.user_id = 나 AND todos.completed = false` (해당 room_id), `todos.created_at` 등록순으로 최대 5개. **방 전체 보충 로직 폐기(2026-07-27)** — `full_spec.md`/구 `design_full_spec.md` 원본이 "내 담당 투두만"이라고 명시하는데 기존 0005는 이를 오독해 5개 미달 시 방 전체 미완료로 채웠다. 내 담당이 5개 미만이면 있는 만큼만 표시하고 빈 슬롯을 채우지 않는다. 마감 없음(0002 확정)이므로 "오늘"은 날짜 필터가 아니라 "내 담당 미완료 우선순위 리스트"를 의미하며, 정렬 기준은 등록순(`created_at`)이다 — `todos`에 날짜/마감 필드가 없으므로 "날짜 기준 우선순위"(full_spec 3-2-4)는 등록순으로 해석한다(0002 참고).
- **아카이브 미리보기**: 사용자 확정 — `archive_items` (해당 room_id) `created_at` 최신순 최대 4개. **가로 스냅 캐러셀**(16px 라운드 텍스트 오버레이 카드, 썸네일 위 스크림 + 제목, 핀/좋아요 뱃지). 각 카드에 **폴더명·태그**를 함께 표시(구 `design_full_spec.md` S-04-5 "썸네일+폴더명+태그") — `archive_folders.name`, `archive_item_tags` 필요. **아카이브 탭(0010) 구현 시점에 `ArchiveBrief` DTO를 folder/tags 포함하도록 함께 확장한다** — 아직 아카이브 탭 자체가 미구현이라 이번 패치에서는 스펙 문구만 반영. `pinned`/좋아요 수는 이 화면에서 정렬 기준으로 쓰지 않는다(항목 카드에 좋아요 수/핀 표시만 동반 — design.md 카드 규격).
  - **2026-08-06 변경(핀 우선 미리보기, 구현 완료)**: 홈 미리보기는 별도 필드 **`previewArchives`**(정렬 = `pinned=true` 우선 → `createdAt` 최신순, **최대 4개**)를 쓴다. 핀 자료로 앞을 채우고 부족분을 최신 비핀으로 보충하며(핀 5+면 핀 최신 4, 핀 0이면 최신 4), **방에 자료가 아예 없을 때만 빈 배열**(그때만 모아보기 드롭존 빈 상태). 기존 **`recentArchives`는 순수 최신순 그대로 유지**(다른 화면 대비, ⓑ안). 서버는 `DashboardResponse.previewArchives`를 `ArchiveItemRepository.findByRoomIdAndCrawlStatusNotOrderByPinnedDescCreatedAtDesc`(핀 개수와 무관하게 정렬+LIMIT 한 번으로 충분, 별도 병합 로직 없음)로 채운다. FE는 서버 미반영에 대비해 **`DashboardData.previewArchives` 게터가 `_previewArchives ?? recentArchives`로 폴백**하던 코드가 그대로 있어(forward-compatible), 이 필드가 오는 즉시 자동으로 핀 우선이 적용됐다 — 앱 쪽 추가 변경 없음.
  - **2026-08-07 신규(핀 전용 미리보기, 백엔드 요청, ⓑ안)**: 위 `previewArchives`와는 별개로 **`pinnedArchives`** 필드를 추가했다 — **순수 `pinned=true` 필터**(최신순, 최대 4개), **핀이 하나도 없으면 빈 배열**(비핀 자료로 채우지 않음). `previewArchives`(패딩됨)와 의미가 다르므로 이름도 다르게 남겨두고 **둘 다 유지**한다 — 요청 출처가 다른 두 소비자가 각자 다른 채움 규칙을 원할 수 있어서다. 서버는 `ArchiveItemRepository.findByRoomIdAndCrawlStatusNotAndPinnedTrueOrderByCreatedAtDesc`로 채운다. **앱은 아직 이 필드를 쓰지 않는다** — 어느 화면이 `pinnedArchives`를 소비할지는 후속 프론트 작업(`specs/OPEN.md` 기록).

## 엣지케이스
- **멤버가 나 혼자뿐인 방**: 아바타줄에 본인 1개만 표시, 정상 동작(빈 상태 아님).
- **내 담당 미완료가 5개 이상**: 등록순 상위 5개만 표시.
- **내 담당 미완료가 0개**: 빈 상태 표시(방 전체로 보충하지 않음).
- **아카이브 4개 미달(0~3개)**: 있는 만큼만 표시, 빈 슬롯이나 placeholder 카드로 채우지 않음.
- **여러 ACTIVE 방 보유 시 홈 컨텍스트**: 0003 재진입 리다이렉트 로직("마지막 본 방")을 그대로 따름 — 이 스펙에서 별도 로직 추가 안 함.
- **주간캘린더 자정 경계**: "이번 주"는 클라이언트 로컬 타임존 기준 월요일~일요일로 고정(서버 `date`는 타임존 없는 date 타입 — 0002 참고).
- **당겨서 새로고침(pull-to-refresh)**: 0001 확정된 폴링 원칙에 따라 S-04 전체를 당겨서 새로고침 가능해야 한다(진행률·아바타·오늘투두·캘린더·아카이브 전부 재조회).
