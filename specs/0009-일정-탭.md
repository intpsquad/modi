> 관련 스펙: `specs/full_spec.md` §6, `specs/0002-data-model.md`(`schedules`), `specs/0003-navigation.md`(`/schedule` 라우트, 현재 placeholder), `specs/0005-홈-대시보드.md`(홈 주간캘린더가 이 스펙의 `schedules` 데이터를 읽기전용으로 미리보기).
>
> 2026-07-27: 화면 상세 원본이던 `specs/design_full_spec.md`(S-xx)는 폐지되고 **이 문서가 해당 화면의 진실**이 됐다. 디자인 토큰·컴포넌트 규칙은 `specs/design.md`(v4, Airbnb 철학).

## 목적
방 멤버가 방 전체 공용 일정을 월간 그리드로 보고, 날짜를 탭해 그날의 일정을 확인·생성·수정한다.

## 하지 않을 것
- **ToDo 표시** — full_spec §6 "일정만 표시(Todo는 표시 안함)". `todos`와 `schedules`는 완전히 독립.
- **홈 주간캘린더의 생성/수정** — `specs/0005-홈-대시보드.md` 확정: 홈 캘린더는 읽기전용 미리보기. 생성/수정은 이 스펙(S-20-A/B)에서만.
- **담당자 지정** — `schedules`에 담당자 필드 없음(0002 확정). 일정은 팀 전체용.
- **반복 일정, 알림(마감임박 알림 등)** — 원본 문서에 언급 없음. 필요해지면 `specs/OPEN.md`에 기록 후 확정.

### 리디자인(2026-08-02 / 184·185·187·188)
목업 3장에 맞춰 구현 리스타일. 디자인 값은 `specs/design.md` 토큰만 사용.
- **월간 그리드**: **일요일 시작**(일~토). 선택일 = primary 채운 원 + onPrimary 텍스트, 오늘(비선택) = primary 텍스트, 일정 있는 날 = 원 아래 연분홍 점(primary @ 45%, 다중일이면 구간의 모든 날짜에).
  - **일요일·공휴일 빨간색**(2026-08-07 사용자 확정, 종전 "일요일 라벨 primary"에서 변경): 요일 헤더 `일` 라벨과 **일요일·공휴일 날짜 숫자**를 `color.accent-danger`(#C13515)로 그린다. **토요일은 색을 주지 않는다**(평일과 동일). 일요일과 공휴일은 색으로 구분하지 않는다.
  - **색 우선순위**: **선택일 > 오늘 > 휴일 > 평일.** 선택·오늘은 사용자가 지금 조작 중인 상태라 날짜 속성보다 앞선다 — 일요일을 탭하면 빨강이 아니라 primary 채운 원 + 흰 글씨가 된다.
  - **공휴일 판정**: `app/lib/features/schedule/korean_holidays.dart`의 **연도별 하드코딩 표**(현재 2026·2027). 음력(설날·추석·부처님오신날)과 대체공휴일 때문에 규칙 계산이 불가능해 확정 날짜를 박아 둔다. **표에 없는 연도는 공휴일을 칠하지 않는다**(일요일 빨간색은 표와 무관하게 계속 동작) — 갱신 책임과 공공데이터포털 API 전환 검토는 `specs/OPEN.md`. 색 토큰 근거는 `specs/design.md` §의미색 주.
- **오늘 일정 카드**: 흰 배경 + `radius.card`(16) + `border` + 좌측 세로 컬러 바(primary) + 제목 + 부제 "`[M월 D일 - M월 D일 ·] [오전/오후 h:mm[ - 오전/오후 h:mm] ·] [장소]`"(다중일이면 날짜 범위, 종료 시간이 있으면 시간 범위, 셋 다 없으면 부제 생략). **좌측 컬러 바 개념은 홈 주간캘린더 카드(`week_calendar.dart`)와 공유하되, 이 화면 카드는 탭 가능한 본카드라 라운드 16·테두리로 더 크게 쓴다**(홈은 읽기전용 미리보기라 `radius.small`(8)·무테).
  - **치수 확정(2026-08-07, Figma 오토레이아웃 실측)**: 카드 **패딩 가로 12 / 세로 10**, 바↔텍스트 **간격 10**, 좌측 바 **3 × 34 · 반경 2**(카드 높이를 채우지 않고 **세로 중앙 고정** — 종전 "4px 풀 하이트 띠"에서 변경), 부제 타이포 `caption`(13/16, 종전 `body-small` 14/20), **카드 사이 간격 8**(카드 "사이"에만 — 마지막 카드 뒤 여백 없음). 채우기 `surface`·외곽선 `border` 1px·반경 16은 종전과 동일.
  - **카드 높이 58은 설정값이 아니라 파생값**이다: `패딩 10 + max(콘텐츠, 바 34) + 패딩 10`. 부제가 있으면 콘텐츠 = `제목 20 + 간격 2 + 부제 16 = 38`이라 58이 된다. **부제가 없는 카드(시간·장소·기간이 전부 없는 경우 — 위 부제 규칙상 허용된다)는 콘텐츠가 제목 20뿐이라 바 34가 하한이 돼 54가 된다.** Figma가 그 케이스를 재지 않았으므로 54는 구현 파생값이다. 타이포를 바꾸면 함께 움직인다. 구현은 **헤어라인 두께 1을 패딩에서 뺀다** — Figma의 "내부(inside)" 스트로크는 프레임 크기를 안 늘리는데 Flutter `BoxDecoration.border`는 자식을 밀어내, 그대로 두면 58이 아니라 60이 되고 바의 x도 12가 아닌 13이 된다.
  - ⚠️ **10·3·34·2는 `design.md`의 4px 스케일 밖 값**이다(12=`spacing.md`, 8=`spacing.sm`만 토큰). 디자이너 확정값이라 반영했고 정식화 여부는 `specs/OPEN.md` 미결 — 임의로 토큰에 맞춰 반올림하지 않는다.
  - 부제는 **문자열 하나**(`' · '` 조인)로 유지한다. Figma는 조각 간격 6px의 가로 오토레이아웃이지만, 육안 차이가 작고 한 덩어리 말줄임(`maxLines: 1`)을 지키는 편이 장소 100자 상한에 안전하다(2026-08-07 사용자 확정).
- **생성/수정 시트**: 그리퍼 + "M월 D일 일정 추가/수정" 제목 → 제목 입력 → 메모 입력 → 기간·시간·종료·장소 그룹 박스(라벨 + 값 + 해제(×) + chevron. 기간=`showDateRangePicker`·해제 없음(시작일 필수), 시간=종일 기본·`showTimePicker`·해제 시 종료 시간도 함께 해제, 종료=시간이 있어야 행 노출·미설정 기본·`showTimePicker`, 장소=미지정 기본·텍스트 입력 다이얼로그) → CTA(추가하기/저장) → (수정 시)"일정 삭제" 링크. 제출 전 클라이언트 검증(종료 날짜<시작 날짜, 같은 날 종료 시간≤시작 시간)이 서버 400과 동일한 규칙으로 먼저 막는다.

## 데이터 (엔티티 연결)
- **schedules**: `room_id`, `title`(필수), `date`(필수), `time`(선택), `end_date`(선택, 다중일 지원), `end_time`(선택), `detail`(선택, 폼 라벨 "메모"), `place`(선택, VARCHAR(100), `V8` 2026-08-03 , MR !52), `created_at`. 정렬은 `date` 오름차순, 동일 날짜는 `time` 오름차순(null은 맨 앞 — 종일 일정이 시간 있는 일정보다 먼저 보이는 게 통상적인 캘린더 UX). 서버가 `nulls first`로 직접 정렬하므로 클라이언트가 재정렬할 필요 없다.
- **`place` 백엔드 구현 완료**(2026-08-03): `schedules.place` 컬럼 + `Schedule` 엔티티 / `ScheduleResponse` DTO / `Create·UpdateScheduleRequest`에 `place` 반영, GET 응답에 포함.
- **종료 시간·다중일(기간) 백엔드 구현 완료**(2026-08-04, 사용자 요청 — 과거 "시간은 단일 값 유지" 방침을 뒤집음): `schedules.end_date`/`end_time`(`V11`, 둘 다 nullable) + 엔티티/DTO 반영. `end_date`가 `date`와 같으면 서버가 저장 시 `null`로 정규화(단일일 표현을 하나로 고정). 검증: 종료 날짜는 시작 날짜보다 빠를 수 없음, 종료 시간은 시작 시간이 있어야 설정 가능, 같은 날 안에서는 종료 시간이 시작 시간보다 늦어야 함(다중일이면 이 순서 제약 없음) — 위반 시 400.
- 조회는 **구간 겹침**(`date <= 조회끝 AND coalesce(end_date, date) >= 조회시작`) 기준이다 — 다중일 일정이 조회 구간보다 먼저 시작해도 구간 안으로 걸치면 조회돼야 하므로 단순 `date BETWEEN`으로는 부족하다(`ScheduleRepository.findOverlappingByRoomId`).
- 월간 그리드 조회 범위: 화면에 보이는 달의 1일~말일(달력 그리드 채우기용 앞뒤 여백 날짜 포함 여부는 UI 구현 시 결정, 데이터 조회는 해당 월 range로 충분) — 위 겹침 기준 덕에 앞 달에서 시작해 이 달로 걸치는 일정도 자동으로 포함된다.
- 홈 주간캘린더(0005)와 동일 테이블·같은 리포지토리 메서드(`findOverlappingByRoomId`)를 공유한다. 대시보드 전용 DTO `ScheduleBrief`도 2026-08-05부터 `endDate`·`endTime`을 모두 내려준다 — 홈 카드가 이제 서버 원문을 가공 없이 쓰지 않고 `formatServerTimeKorean`(`schedule_time_format.dart`)으로 초를 제거해 표시하므로 원본 문자열 노출 부작용이 없다.

## 엣지케이스
- **월 경계 이동 시 캐시**: 이전에 조회한 달은 재조회하지 않고 캐시해도 되나, 저장 후에는 현재 보고 있는 달을 반드시 재조회한다(신선도 우선, 0001 폴링 원칙과 일치).
- **하루에 일정 다수**: 카드 리스트에 전부 표시, 별도 접기/펼치기 없음(원본에 명시 없음, 개수 제한도 없음).
- **글자 수 제한**: 원본에 명시 없음 — 저리스크 기본값으로 제목 1~50자, 메모(설명) 500자 이내(0006 투두 제목/상세와 동일 기준 재사용), 장소 100자 이내.
- **주 시작 요일 불일치**: 이 화면(월간)은 **일요일 시작**(목업), 홈 주간캘린더(0005)는 **월요일 시작**. 앱 내 불일치라 `specs/OPEN.md`에 통일 여부 미결로 기록(2026-08-02, 사용자 확정: 이 화면은 목업대로 일요일 시작).
- **휴일 색 불일치**: 일요일·공휴일 빨간색은 **이 화면에만** 들어갔다(2026-08-07). 홈 주간캘린더(`week_calendar.dart`)는 손대지 않아 같은 날짜가 한쪽은 빨갛고 한쪽은 검다 — 위 주 시작 요일 항목과 같은 축으로 `specs/OPEN.md`에 기록.
- **공휴일 표의 노후화**: 표에 없는 연도로 넘기면 공휴일이 안 칠해진다(일요일은 계속 빨강). 2026년에만 「공휴일에 관한 법률」이 두 번 개정돼 제헌절이 부활하고 노동절이 추가된 전례가 있어, 매년 월력요항 발표 후 표를 확인해야 한다 — `specs/OPEN.md`.
