    - **"임의 추정"이 아닌 근거**: 요약 프롬프트가 **평서문(`~한다`, `~다`)을 못 박고** 있어 문장 경계가 문법으로 정해진다. 동결 픽스처 15건에서 종결 부호는 마침표뿐이고 `!`·`?`는 0건이었다.
    - ⚠️ **함정 둘이 실제 데이터에 있다** — ① 콘텐츠 이름 `드.디.어.`는 마지막 마침표 뒤에 공백이 와서 단순 분리 시 한 문장이 두 줄로 찢어진다 ② `~보자.`처럼 **`다`로 끝나지 않는 문장**이 있다. 그래서 종결 어미를 열거하지 않고 "마침표 앞 어절에 다른 마침표가 있으면 약어로 본다"로 판정한다.

  2. **본문 루트 선택** — `main` / `[role=main]` / `article` 중 **텍스트가 가장 긴 것**. 첫 번째가 아니다 — `article`을 목록 카드로 쓰는 사이트에서 홍보 카드가 선택되는 사고가 실측됐다.

  4. **문단 유지** — 블록 경계를 개행으로 남긴다(Jsoup의 `text()`는 문서 전체를 한 줄로 만든다).

## 엣지케이스
- **폴더 삭제 시 하위 자료**: `ON DELETE CASCADE`이므로 복구 불가 — 확인 모달 문구에 반드시 명시.
- **URL이 아닌 순수 텍스트 등록**: `url`은 null, `body_text`만 채워짐 — AI 태깅은 `body_text` 기준으로 동일하게 동작.
- **AI 태깅 실패/타임아웃**: 태그 없이 등록 허용(2026-07-27 확정, `specs/OPEN.md` 확정 기록 참고) — 등록 자체는 막지 않는다.
- **동일 자료 여러 폴더 등록**: 원본에 "폴더 이동"만 언급되고 "복사"는 없음 — 자료는 폴더 1개에만 속한다(현재 `archive_items.folder_id` 단일 FK와 일치).
- **좋아요/핀은 상세(S-25-B)에서만 토글 가능한지, 목록(S-25-A)에서도 가능한지**: 구 design_full_spec S-25-A는 목록에 좋아요 수만 "표시"한다고 되어 있고 토글 위치는 S-25-B로 명시됨 — 목록에서는 표시만, 토글은 상세에서만.
