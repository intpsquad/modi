# 0013 — 종료된 방 요약 홈 & 재시작 (S-05, S-12) *(후순위)*

> 관련 스펙: `specs/full_spec.md` §3-3/§9-3, `specs/0002-data-model.md`(`rooms.status`, "종료 요약" 계산값), `specs/0004-방-생성-참여.md`(S-10과 동일 필드를 S-12가 재사용), `specs/0008-방-전환.md`(S-07 종료 방 탭 → S-05), `specs/0012-설정.md`(S-40-D → S-05).

>
> **개발 우선순위: 후순위** — `full_spec.md`/구 `design_full_spec.md` 원본 모두 이 화면을 "후순위/MVP 1차 스코프에서 제외 가능"으로 명시. 이 스펙은 나중에 바로 구현할 수 있도록 미리 문서화만 해둔다.

## 목적
목표 기간이 끝나 `ENDED` 상태가 된 방에 진입했을 때, 최종 성과를 읽기전용으로 요약해 보여주고 원하면 기간을 연장해 재시작(`ACTIVE` 복귀)하게 한다.

## 하지 않을 것
- **이 스펙에서 다루는 화면의 실제 구현 우선순위 결정** — MVP 1차에 포함할지는 PROJECT_PLAN 로드맵에서 별도 결정.

## 방 자동 종료 전환 (4-3, 구현 완료 — 2026-07-30)
`end_date` 경과 시 `ENDED` 자동 전환(0002 확정)의 검사 시점은 **요청 시점 lazy 체크**로 확정했다(배치/`@Scheduled` 아님, `specs/OPEN.md` 확정 기록). 별도 배치 인프라 없이 `RoomService.refreshStatus(Room)`가 이미 `ACTIVE`인 방이 `LocalDate.now().isAfter(room.getEndDate())`면 그 자리에서 `room.end()` + 저장까지 하고, 방을 읽는 모든 진입점이 이를 거친다: 초대 미리보기(`previewInvite`)·참여(`joinRoom`, `resolveRoom` 경유)·내 방 목록(`listMyRooms`)·지난 방 목록(`listPastRooms`)·홈 대시보드(`DashboardService.getDashboard`). `end_date` 당일까지는 `ACTIVE`를 유지하고 다음날부터 `ENDED`로 전환된다(`isAfter`, 경계 테스트 `roomEndingTodayStaysActiveUntilDayAfter`로 확인). 이 전환 덕분에 이전에는 실제로 존재하던 버그(만료된 방에 새 멤버가 계속 join 가능)도 함께 해소됐다.

## 데이터 (엔티티 연결)
- **최종 완료율**: 0002 "방 진행률" 계산값(완료 todos / 전체 todos)을 종료 시점 스냅샷이 아니라 **현재 시점 재계산**으로 보여준다(원본에 "종료 시점 고정 스냅샷" 언급 없음 — ENDED 방은 어차피 데이터가 더 안 바뀌므로 실질적으로 동일).
- **내가 처리한 투두 개수**: 본인이 `completed=true`로 만든 투두 수 — 현재 `todos`에는 "누가 완료 처리했는지" 기록하는 컬럼이 없다(`completed_at`만 있고 완료자 없음). **스키마 확장 필요 여부는 `specs/OPEN.md`에 기록** — 대안으로 "본인 담당 완료 투두 수"(담당자 기준, 신규 컬럼 불필요)로 근사할 수도 있음, 확정 전까지 후자로 임시 해석.
- **콕찌르기 당한 횟수**: `pokes` where `to_user = 나 AND room_id = 이 방` count.
- **가장 열심히 한 멤버**: 0002 개인 진행률 계산값 중 최댓값 멤버.
- **아카이브 하이라이트("가장 많이 조회된")**: `archive_items`에 조회수 컬럼이 없다 — `specs/0010-아카이브-탭.md`에서 이미 `specs/OPEN.md`로 넘긴 미결 사항과 동일 이슈. 확정 전까지는 좋아요 수 최다 항목으로 근사.
- **`rooms.status` 자동 전환**: `end_date` 경과 시 `ENDED`(0002 확정). 검사 시점은 요청 시점 lazy 체크로 확정·구현 완료(위 "방 자동 종료 전환" 절 참고).

## 성공(인수) 기준
- [ ] `ENDED` 방에 진입하면 S-04가 아니라 S-05 레이아웃이 표시된다.
- [ ] S-05의 모든 카드는 읽기전용이며 체크박스/좋아요/콕찌르기 등 어떤 조작도 발생하지 않는다.
- [ ] "재시작"을 탭하면 S-12로 이동하고, 기존 방 정보가 프리필된 채 기간만 새로 입력할 수 있다.
- [ ] S-12에서 저장하면 방 상태가 `ACTIVE`로 바뀌고 기존 멤버 구성은 그대로 유지된 채 `/home`으로 이동한다.

## 엣지케이스
- **재시작 후 이전 종료 요약 데이터**: 재시작(`ACTIVE` 복귀) 이후에는 진행률 계산이 새 활동을 포함해 계속 누적되므로, "이전 시즌"과 "재시작 후" 구분이 필요한지는 원본에 없음 — 현재는 구분하지 않고 누적치로 취급.
- **여러 번 재시작 반복**: 별도 "시즌" 개념 없이 `rooms` 1행이 계속 상태만 왕복(`ACTIVE`↔`ENDED`) — 히스토리 보존이 필요해지면 별도 스펙 확정 필요.
