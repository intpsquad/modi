- [ ] **자바스크립트로 그리는 사이트(SPA)는 크롤링이 원천적으로 불가능하다 — 지금은 두고 기록만** *(2026-08-08 신규, 운영 데이터의 아고다 링크 "분석 실패" 조사)* — 사용자 확정: **이번엔 고치지 않고 기록만 한다**(AskUserQuestion).
  - **실측**: `https://www.agoda.com/ko-kr/cheongpyeong-riverside-park/hotel/gapyeong-gun-kr.html?…`를 `JsoupUrlCrawler`와 같은 조건(리다이렉트 미추종, 봇 UA)으로 요청하면 **HTTP 200 · HTML 260KB**가 오는데 그 안에 **글자가 0자**다. `<title></title>`이 **비어 있고**, `og:title`·`og:image`·`name="description"`이 **하나도 없으며**, `application/ld+json` 스크립트 태그는 **내용이 빈 채로** 자리만 있다. `<body>`는 `<div id="login-react-root">` 류 빈 마운트 지점 + `<script>` 28개뿐 — 호텔 이름·사진·설명은 전부 **브라우저가 JS를 실행한 뒤에** 만들어진다.

  - **화면의 증상 3개가 전부 여기서 나온다**(`JsoupUrlCrawler.toCrawlResult`): ① `og:title` 없음 → `doc.title()`도 빈 문자열 → `title = url`이라 **카드 제목이 URL 원문**으로 뜬다 ② `og:image` 없음 → `null` → **썸네일 회색 자리** ③ `bodyText.isBlank()` → `CrawlException("본문을 찾을 수 없는 링크예요")`. ③은 `retryable`이 아니라 `ArchiveCrawlProcessor`의 20분 재시도(최대 4회)를 **타지 않고 즉시 FAILED로 확정**된다 — 그래서 2026-08-01 등록분이 지금도 "분석 실패"다.

    - **(A) 헤드리스 브라우저**(Playwright/Puppeteer) — 아고다뿐 아니라 **모든 SPA**가 살아나는 유일한 일반해. 대신 Chromium이 Docker 이미지에 ~400MB, 렌더 1건에 2~5초 + 메모리 300MB 이상. **서버 한 대에 Caddy·Postgres·Redis·MinIO·Spring·FastAPI가 이미 같이 떠 있어**(`deploy/docker-compose.*.yml`) 부담이 크다. `archiveCrawlExecutor`가 max 4스레드라 동시 4건이면 1.2GB+.
    - **(B) URL 슬러그로 제목만 만들기** — `cheongpyeong-riverside-park` → "Cheongpyeong Riverside Park". 비용 거의 0이고 아고다 전용이 아닌 **일반 폴백**이라 모든 SPA에 듣는다. 썸네일·본문·AI 태그·요약은 여전히 없다.
    - **(C) 제목 직접 수정** — 지금 ⋮ 메뉴는 링크 수정·메모 추가뿐이고 **제목 수정이 없다**. 자동으로 절대 못 가져오는 사이트의 최종 해결책이지만 앱+서버 양쪽 작업이다.

- [ ] **첨부한 사진을 떼는 수단이 없다** *(2026-08-25 #65 조사 중 발견)* — 폼의 "이미지 추가" 박스는 **바꾸기만** 되고 해제가 안 된다(`_existingImageUrl` 이 `late final` 이라 지우는 경로 자체가 없다). 서버는 `imageUrl` 을 비워 보내면 해제하도록 이미 되어 있으므로 앱만 붙이면 된다. 다만 지금은 "안 보낸 것"과 "비우려는 것"이 같은 요청이라, 해제 UI 를 넣으려면 **의도적 null 과 생략을 구분하는 상태 설계**가 먼저다(`TodoItem.copyWith` 의 센티널과 같은 문제). 선택지 ⓐ 미리보기 위에 ✕ 버튼 ⓑ 이미지 박스 옵션창에 "사진 제거" 항목 추가 ⓒ 지금대로(바꾸기만). 사진을 잘못 붙였을 때 되돌릴 방법이 없다는 민원이 나오면 ⓑ가 자연스럽다.
