# MODI 협업 캐릭터 — 백엔드 핸드오프

> 작성: 2026-08-06 (프론트/디자인) · 대상: 백엔드
> 프론트는 UI만 담당. 아래 **판정·집계·API·스키마는 백엔드 구현 대상**이다.
> 미확정 결정 추적은 `specs/OPEN.md`(투두 마감일 · 접속/조회 로그 항목) 참조.

## 0. 개요

- **무엇**: 마이 탭 프로필에 표시하는 "협업 캐릭터". 프로젝트를 넘나들며 누적되는 개인 정체성·성장 표현. (당근식 "온도"는 폐기 → **캐릭터 + 진화**)
- **원칙**
  - **100% 자동** — 동료 평가/상호 칭찬 **없음**. 모든 판정은 행동 로그에서 자동.
  - **밉지 않게** — 느긋 캐릭터도 "이번 시즌(가변) + 자학개그 카피 + 진화 경로"로 상처 안 주게.
  - **판정은 서버에서** — 로직·임계값을 서버에 단일화(앱 중복·드리프트 방지). 앱은 결과만 표시.

## 1. 캐릭터 최종 명단

### 😴 느긋 계열 (진화 전)
| id | 이모지 | 이름 | 카피 | 판정 신호 |
|---|---|---|---|---|
| `PROCRASTINATOR` | 🦥 | 미루기 장인 | "내일의 나를 믿는 타입" | 타이밍=미룸 + 완료율 낮음 |
| `GHOST` | 🫧 | 잠수 요정 | "가끔 사라졌다 나타나는" | 완료 공백 큼(며칠 무활동 후 등장) |
| `LURKER` | 👀 | 눈팅 요정 | "다 보고는 있어요" | 접속·조회 많은데 완료 적음 |
| `TURTLE` | 🐢 | 마이 페이스 | "급할 거 없잖아?" | 느리지만 완주(완료율 유지) |

### 🔥 갓생 계열 (진화 후 · 목표)
| id | 이모지 | 이름 | 카피 | 판정 신호 |
|---|---|---|---|---|
| `STEADY` | 🌱 | 꾸준 적립가 | "하루도 안 빼먹는" | 완료 간격 규칙적 + 스트릭 김 |
| `SPRINTER` | ⚡ | 막판 스퍼트 | "데드라인이 원동력" | 타이밍=미룸이지만 완료율 높음(결국 해냄) |
| `EARLYBIRD` | 🚀 | 미리미리단 | "제일 먼저 끝내고 여유" | 타이밍=미리(마감 훨씬 전/등록 직후 완료) |
| `THE_J` | 🏆 | 이 구역 J | "계획의 신, 완벽한 J" | 완료율·마감준수·꾸준 종합 최상 |

### 보조·기타
| id | 이모지 | 이름 | 카피 | 판정 신호 |
|---|---|---|---|---|
| `CHEERLEADER` | 💛 | 응원 요정 | "팀 분위기 담당" | 남에게 좋아요 많이 줌(활동량과 별개 보조) |
| `WARMING_UP` | 🌫️ | 아직 분석 중 | "곧 캐릭터가 정해져요" | 완료 투두 < N(콜드스타트) |

### 🍜 취향 태그 (옵션 · 서브 · 캐릭터 옆 작은 뱃지)
`🍜 밥에 진심` · `🏨 숙소 헌터` · `🛍 쇼핑 큐레이터` · `🎬 레퍼런스 요정` · `📚 자료 도서관` · `📍 장소 탐험가`
→ 아카이브 자동 태깅(`archive_item_tags`)에서 사용자가 가장 많이 등록한 카테고리로 산출. 넣을지는 옵션(복잡도↑).

> **구분 포인트** — 🦥 미루기 장인 vs ⚡ 막판 스퍼트: 둘 다 늦게 하지만 미루기 장인은 **완료율 낮음(놓침)**, 막판 스퍼트는 **완료율 높음(늦어도 해냄)**.

## 2. 진화 사다리 (성장 동기)

```
🦥 미루기 장인 ─▶ ⚡ 막판 스퍼트 ─▶ 🚀 미리미리단 ─▶ 🏆 이 구역 J
🫧 잠수 요정   ─▶ 🌱 꾸준 적립가 ─▶ 🚀 미리미리단 ─▶ 🏆
👀 눈팅 요정   ─▶ 🌱 꾸준 적립가
🐢 마이 페이스 ─▶ 🌱 꾸준 적립가
```
- 프로필에 "다음 캐릭터까지 진화 바 + 조건"(예: `🌱 꾸준 적립가로 진화까지 · 3일 연속 완료`) 표시.
- 캐릭터는 **"이번 시즌"(최근 행동 기준, 가변)** — 영구 낙인이 아니라 지금의 나. 좋아지면 진화.

## 3. 판정 로직 (마감일이 옵션 → 없어도 강건)

마감일이 **옵션**이라 "마감 없는 완료 투두"가 다수일 수 있음. → **있으면 마감 / 없으면 리드타임**으로 폴백하는 층상 판정.

### 3-1. 투두 1개의 "타이밍 점수" (완료된 투두, −1 미리 ↔ +1 미룸)
- **마감 있으면(1순위·강한 신호):** `completed_at − due_date` → 마감보다 이르면 미리(−), 임박·초과면 미룸(+)
- **마감 없으면(2순위·폴백):** `completed_at − created_at`(리드타임)을 그 방/사용자 분포로 정규화 → 짧으면 미리(−), 길면 미룸(+)

### 3-2. 사용자 집계 (신호 세기로 가중)
```
timing = Σ(투두 타이밍 × 가중치) / Σ가중치
  · 마감 있는 투두 가중치 1.0
  · 마감 없는 투두 가중치 0.5   (약한 신호라 절반)
```
→ 마감 있는 투두가 하나라도 있으면 그쪽을 더 신뢰, 없으면 리드타임만으로도 산출. **마감 비율에 자동 적응.**

### 3-3. 다른 축 (별도 집계)
- **완료율** = 담당 완료 / 담당 전체
- **꾸준함** = 완료일 규칙성 · 최고 스트릭
- **완주** = 방이 ENDED 될 때까지 잔류(중도 이탈 X)
- **활동성** = 접속·조회 빈도 대비 완료 빈도 (→ 눈팅/잠수 구분)
- **도움(보조)** = 남에게 준 좋아요 수

### 3-4. 캐릭터 배정 (timing × 완료율 × 활동성)
- 활동성 낮음(접속만·완료 적음) → `GHOST`/`LURKER`
- 완료 있음 + 미룸 + 완료율 낮음 → `PROCRASTINATOR`
- 완료 있음 + 미룸 + 완료율 높음 → `SPRINTER`
- 미리 + 규칙적 → `EARLYBIRD`/`STEADY`
- 종합 최상 → `THE_J`
- (보조) 남에게 좋아요 최상위 → `CHEERLEADER` 부여 가능

### 3-5. 데이터 희박 가드 (필수)
- **완료 투두 < N(예: 5) → `WARMING_UP`** — 억지 배정 금지(신규·저활동 오판 방지)
- 마감 있는 투두 비율이 낮으면 "마감형/미리형" 정밀도만 낮아지고, 자연히 **꾸준·완주·활동성 축 캐릭터로 수렴**. 판정 자체는 안 깨짐(graceful degradation).

### 3-6. (옵션) 넛지
마감 없는 투두가 대부분이면 앱에서 *"마감을 정하면 캐릭터가 더 정확해져요"* 안내 한 줄(강제 아님).

## 4. 백엔드 해야 할 것

### 4.1 [신규] `todos.due_date` (옵션 마감일)
- `todos`에 `due_date` DATE **nullable** 컬럼 (새 Flyway 마이그레이션). 필요 시 `due_time` TIME nullable.
- `TodoResponse` + 투두 생성/수정 API에 포함.
- ⚠️ **`specs/0002` "마감 없음 확정"(2026-07-27 재확인)을 되돌리는 변경**. 파급: 마감일순 정렬·"오늘 마감" 필터·"마감 임박 알림"(현재 `notification_settings`에서 일부러 제외됨) 재검토. 상세 = `specs/OPEN.md`.

### 4.2 [신규] 접속·조회 로그
- append-only 테이블 예: `user_activity(id, user_id, room_id, kind, target_id NULL, created_at)`
  - `kind` = `APP_OPEN` · `ROOM_VIEW` · `ARCHIVE_ITEM_VIEW` · `TODO_VIEW` …
- 기록 지점: 앱 진입 · 방 진입 · 자료 상세 열람 시 이벤트 적재.
- ⚠️ 개인정보(방 내부 한정·집계 전용·보존기간) + 볼륨(일별 집계/TTL) 고려.

### 4.3 [신규] 캐릭터 판정·집계 + API
- 위 3장 로직으로 캐릭터/진화/특징을 **서버에서** 산출.
- 엔드포인트 예:
  - `GET /me/character` — 내 캐릭터(마이 탭)
  - `GET /rooms/{roomId}/members/{userId}/character` — 멤버 조회(선택)
- **응답 계약(예시)**
  ```json
  {
    "characterId": "PROCRASTINATOR",
    "name": "미루기 장인",
    "emoji": "🦥",
    "copy": "내일의 나를 믿는 타입",
    "why": "등록만 해두고 한참 뒤에 몰아서 끝내고 있어요",
    "evolveTo": "STEADY",
    "evolveProgress": 0.55,
    "evolveHint": "3일 연속 완료하면 진화해요",
    "tasteTag": "FOOD",
    "confidence": "LOW",
    "activityStats": {
      "completed": 128,
      "streak": 19,
      "deadlineKeptRate": 0.78,
      "helpGiven": 23,
      "shared": 12,
      "dueDateCompletedCount": 5
    }
  }
  ```
  - `confidence`: 마감 있는 투두 비율/완료 수가 적으면 `LOW`(앱에서 "대략" 뉘앙스 표시용).
  - `tasteTag`: 취향 태그 도입 시에만.
  - `dueDateCompletedCount`(2026-08-09 추가): 마감일 있는 완료 투두 수. **`deadlineKeptRate`가 0.0이어도 이 값이 0이면 "마감 준수 0%"가 아니라 "잴 데이터 없음"** — 마감일을 설정한 완료 투두가 하나도 없는 사용자에게 "마감을 전혀 안 지킴"으로 오표시되던 버그를 이 필드로 구분해 고쳤다. 프론트는 이 카운트가 0이면 마감 준수 칩을 숨긴다.

### 4.4 [기존 · 그대로 활용] 집계 소스
`todos.completed / completed_at` · `todo_assignees` · `archive_items.created_by` · `archive_likes.user_id` · `pokes.to_user` · `room_members`(완주) · `archive_item_tags`(취향)

## 5. 착수 순서 / 주의

1. **선행 결정**: 협업 캐릭터 기능 자체가 아직 설계 단계 → 팀 승인 후 스키마 착수.
2. 4.1(마감일) → 4.2(로그) → 4.3(판정·API) 순.
3. `todos.due_date` 되돌림은 여러 스펙(0002/0005/0006/0015)에 파급 → **스펙 갱신 동반** 필요.
4. 접속/조회 로그는 개인정보 민감 → 보존·집계 정책 먼저.
