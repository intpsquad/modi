# 알림 "전체/개별" 동작 변경 — 백엔드 요구사항

> 작성: 2026-08-08 (프론트/디자인) · 대상: 백엔드 · 티켓 
> 관련: `specs/0012-설정.md`(알림 설정), `server/.../global/notification/PushNotifier.java`

## 배경 / 결정
"전체 알림"을 **마스터 차단기 → 일괄 스위치**로 바꾼다(사용자 확정).
- 기존: `allEnabled == false`면 개별 설정과 무관하게 **모든 알림 차단**.
- 변경: **발송은 개별 flag만으로 판정**한다. "전체 알림"은 UI에서 개별을 한 번에 켜고 끄는 편의 스위치이자, 개별이 전부 켜졌는지 나타내는 파생 표시값일 뿐이다.
- 사용자 의도: "모든 알림 받기"를 끈다 = "전부는 말고 **골라 받겠다**". 그래서 전체를 꺼도 개별을 각각 켤 수 있어야 한다.

## 필요한 서버 변경 — **발송 게이트에서 `allEnabled` 제거**
`server/src/main/java/com/nomara/modi/server/global/notification/PushNotifier.java`, **line 63·74 두 곳**:

```java
// 변경 전
.map(s -> s.isAllEnabled() && type.isEnabled(s))
// 변경 후 (개별 flag만으로 발송 판정)
.map(s -> type.isEnabled(s))
```

## 유지 / 주의
- **`all_enabled` 컬럼·DTO 필드는 그대로 둔다.** 프론트가 저장 시 `allEnabled = (개별 7종 모두 ON)`인 파생값으로 계속 보낸다. 수정요청 DTO의 `@NotNull`도 그대로 만족한다. 즉 **스키마·마이그레이션 변경 없음**, 게이트 로직만 수정.
- 프론트는 이미 배포 가능하게 구현됨 — 개별 토글이 항상 활성이고, 전체 토글은 일괄 세팅. **서버 게이트가 바뀌기 전까지는** "전체 꺼짐 + 개별 일부 ON"이어도 서버가 여전히 `allEnabled &&`로 막아 **실제 알림이 안 오는 불일치**가 있으니, 위 게이트 변경이 함께 배포돼야 한다.
- 테스트: `PushNotifier` / `PushTypeSettingsTest` 등에서 "전체 끄면 전부 차단"을 검증하는 케이스가 있으면 "개별 flag만으로 판정"으로 수정.
- (별건) `knock_enabled` 잔재 제거는 `specs/OPEN.md`의 기존 항목과 함께 처리.

## 프론트에서 이미 끝난 것 (참고)
- 개별 스위치 항상 활성(마스터 차단 폐지), "전체 알림" = 파생/일괄.
- 안내 문구 "전체 알림을 끄면 개별 알림도 모두 꺼져요" 삭제.
- 저장 시 `allEnabled`를 "개별 전체 ON 여부"로 정규화해 전송.
