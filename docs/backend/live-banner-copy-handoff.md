# 백엔드 핸드오프 — 라이브 배너 문구·귀속 규칙 (2026-08-08 QA)

홈 라이브 배너(활동 피드) 문구/귀속에 대한 QA 결정 모음. 대상: `ActivityService`·`TodoService` 담당자.
관련: `docs/backend/home-activity-feed.md`(피드 스펙), `docs/backend/activity-poke-dedup-handoff.md`(콕 중복). FE 문구 조립은 `home_screen.dart`의 `homeActivityMessages`/`_activityEventMessage`.

---

## 1. 완료자 오귀속 확인 (버그 조사)
**증상**: 배너에 "○○님이 투두 N개를 완료했어요 / ○○님이 맡은 투두를 다 끝냈어요"가 뜨는데, 그 사람은 완료를 안 했거나 담당도 아니라고 함.

- **FE는 정상** — 서버가 준 `actorNickname`을 그대로 볼드로 표시하고, 없으면 그 줄을 건너뛴다(이름을 지어내지 않음).
- 서버 코드도 `actor = 인증된 uid`(완료 누른 본인)로 기록하고, `TODO_ALL_DONE`은 **누른 사람이 담당자이고 그 담당 투두가 전부 완료**일 때만 발화(`TodoService.recordCompletionActivity`). 즉 서버 기준으로는 "누른 사람"이 맞게 들어간다.
- ⇒ 확인 필요: 해당 이벤트의 **`activities.actor_user_id`가 실제 조작자와 일치하는지**(QA 계정/로그인 섞임 등 인증 쪽 오귀속 가능성). 인증(Firebase uid) 영역이라 사람 확인 대상.
- 참고: 아래 2번(공동 투두 문구 분리)이 적용되면 "공동 투두를 남이 대표로 눌러 한 사람만 크레딧" 류의 **오해는 상당 부분 사라진다**.

## 2. 공동 투두 완료 문구 (다중 담당자) — 신규
완료 이벤트를 담당자 수로 나눈다:

| 담당 구성 | 문구 |
|---|---|
| **단독**(담당자 1명 = 누른 사람) | `{actor}님이 투두 N개를 완료했어요 🔥` (현행, actor+일자 묶음 유지) |
| **공동**(담당자 2명 이상) | **`{대표닉} 외 {담당자수-1}명이 함께 맡은 투두를 끝냈어요 🎉`** (주체=팀, 단독 크레딧 X) |
| 미지정(담당자 0명, 누구나) | `{actor}님이 투두를 완료했어요` (현행 유지) |

- **대표닉 = 담당자 중 닉네임이 가장 짧은 사람** (길이 최소화). 표시는 FE가 6자 컷(3·4번).
- 공동은 **actor+일자 묶음("N개 완료")과 성격이 달라** 개별 완료 이벤트로 보내는 걸 권장(단독만 묶고 공동은 건별). 서버가 구현 방식을 정하되, FE에는 아래 데이터가 필요.

**서버가 활동에 실어줘야 하는 것(공동 완료 이벤트)**: 담당자 **닉네임 목록**(또는 최소 "가장 짧은 닉네임 1개 + 담당자 총원"). 예) `assigneeNicknames: [...]` 또는 `representativeNickname` + `assigneeCount`.

> **TODO_ALL_DONE은 개인 문구 유지** — "내 담당 투두를 다 끝냄"은 본질적으로 개인 성취라 `{actor}` 그대로 둔다.

## 3. 닉네임 6자 컷 (FE — 구현 완료, 백엔드 무관)
배너에 보이는 모든 닉네임(행위자·콕 대상·공동 대표닉 등)은 **6자까지만, 넘으면 `…`**. 자소 단위로 자른다. 구현: `home_screen.dart`의 `bannerName()`(단위 테스트 `banner_name_test.dart`). 서버는 원본 닉네임을 그대로 주면 되고, 자르기는 FE가 한다.

## 4. 미지정 투두 넛지 — 신규 파생 이벤트
방에 담당자 없는(미지정) 투두가 있으면 배너로 담당 지정을 유도한다.

- **문구(확정)**: **`{n}개의 투두가 주인을 찾고 있어요! 🙋`** (`{n}` = 방의 미지정 투두 개수)
- `NUDGE_NONE_TODAY`·`NUDGE_QUIET_MEMBER`와 같은 **조회 시점 파생 이벤트**(저장 안 함). `n > 0`일 때만.
- 서버가 `count`(미지정 투두 수)를 실어 이벤트 타입(예: `NUDGE_UNASSIGNED`)으로 내려주면, FE가 위 문구로 조립.
- (선택) 배너 탭 시 투두 탭 미지정 섹션으로 이동 — 추후 FE.

## 5. 콕 중복 (기존 핸드오프)
`docs/backend/activity-poke-dedup-handoff.md` 참고 — 시간 윈도우 없이, 콕은 "보낸→받는 당 1건"으로 합침(쿼리 단계 dedup 권장).

---

## FE / BE 분담 요약
- **FE(완료)**: 닉네임 6자 컷(`bannerName`). 아래 서버 데이터가 오면 문구 조립(공동 완료·미지정 넛지)도 FE가 담당.
- **BE(필요)**:
  1. 완료 이벤트에 **담당자 구성**(단독/공동/미지정 구분 + 공동이면 담당자 닉네임/총원) 반영 → 공동 완료 문구용.
  2. **`NUDGE_UNASSIGNED`** 파생 이벤트(미지정 투두 개수 `count`).
  3. `actor_user_id` 오귀속 조사(1번).
  4. 콕 dedup(5번).
