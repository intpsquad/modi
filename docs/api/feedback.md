# 인앱 피드백(문의하기) — API 요약

`POST /feedback` 하나뿐이다. 스펙은 `specs/0012-설정.md`(화면)·`specs/0002-data-model.md`(`feedback` 테이블).
정식 계약은 `docs/api/openapi.json`(springdoc 자동 생성)이고, 이 문서는 **왜 이렇게 생겼는지**를 남긴다.

## POST /feedback

- 인증: 로그인 필요(Firebase ID 토큰)
- `Content-Type: multipart/form-data`
- 응답: `201` + `{ "id": 12, "createdAt": "2026-08-26T…Z" }`

| 파트 | 필수 | 설명 |
|---|---|---|
| `type` | ✅ | `BUG` · `QUESTION` · `SUGGESTION` |
| `content` | ✅ | 본문. 앞뒤 공백은 서버가 잘라 저장. 공백만이면 `400`, 2000자 초과면 `400` |
| `replyEmail` | — | 회신 주소. 비우면 답장할 수 없다는 뜻(앱이 폼에서 그렇게 안내한다) |
| `appVersion` | — | 예: `1.2.0(7)` |
| `deviceInfo` | — | 예: `ios 18.2` |
| `image` | — | 스크린샷 1장. 5MB 이하, JPEG/PNG/WEBP |

### 왜 2단계 업로드가 아닌가

방 대표 이미지(`docs/api/room-cover-image.md`)는 `POST /rooms/cover-image`로 **URL을 먼저 받아** 저장 필드에
넣는 2단계다. 피드백 스크린샷은 그럴 수 없다 — **비공개로 저장**하므로 클라이언트에 돌려줄 공개 URL이
아예 없다. 그래서 파일과 필드를 한 번에 받는다.

### 스크린샷은 왜 비공개인가

사용자 화면 캡처에는 개인정보가 담길 수 있다. `MinioConfig`의 버킷 정책은 `rooms/cover/*`만 공개 읽기로
열어 두고 나머지는 비공개이며, 피드백은 그 기본값을 그대로 쓴다(**버킷 정책 변경 없음** — 인프라 무관).
DB에는 URL이 아니라 오브젝트 키(`feedback/{UUID}.{ext}`)만 남고, 팀에게는 **알림 메일에 바이트를 첨부**해
전달한다.

## 오류

| 상태 | 언제 |
|---|---|
| `400` | 내용이 비었거나 2000자 초과 / 이미지가 5MB 초과 / 매직바이트로 이미지 형식을 판별할 수 없음 |
| `503` | **이미지를 붙였는데** 오브젝트 스토리지가 미설정(`MINIO_ENDPOINT` 없음)일 때 |

`503`인 이유: 이미지를 조용히 버리고 저장을 성공시키면 사용자는 스크린샷이 전달됐다고 믿는다(방 대표
이미지와 같은 판단). **이미지가 없는 제출은 스토리지가 없어도 정상 처리된다.**

## 알림 메일

- 수신 주소: `FEEDBACK_NOTIFY_TO` 환경변수(기본값 `modi.app.team@gmail.com`)
- 🔴 **저장이 진실이고 메일은 부가물이다.** 발송이 실패하거나 `spring.mail.host` 미설정으로 `EmailSender`
  빈이 아예 없어도 **행은 남고 응답은 `201`**이다(로그만 남긴다). 인증코드(`EmailVerificationService`)가
  발송을 먼저 하고 실패 시 저장하지 않는 것과 **반대 순서**다 — 거기선 발송 실패 후 코드가 커밋되면
  사용자가 재시도조차 못 하지만, 피드백은 제출을 잃는 것이 최악이기 때문이다.
- ⚠️ 운영에서 알림이 실제로 나가려면 배포 `.env`에 `SPRING_MAIL_HOST`/`USERNAME`/`PASSWORD`가 있어야
  한다. 없으면 **부팅은 성공하고 알림만 조용히 안 간다**(CLAUDE.md가 경고하는 `@ConditionalOnProperty`
  패턴). 저장은 되므로 데이터를 잃지는 않는다.

## 조회 API는 없다

운영자가 DB나 메일로 본다. "내 문의 내역" 화면이 없어 만들지 않았다 — 필요해지면 그때 추가한다.
